# 섀도 추적과 사전 등록 (`investment_cycle_v4`)

2026-11-02 추가. 매수 승인에 못 미친 전략도 **금액 0의 기록**으로 실전 결과를 쌓고, 그 기록이 **결과를 보기 전에 고정한 문턱**을 넘으면 C등급 소액 매수까지 허용한다. 문턱을 낮춰서 매수가 나오게 만드는 장치가 아니다.

## 왜 필요한가

v3까지는 두 가지가 겹쳐 있었다.

- 사후 평가(`invest review`)는 **매수로 기록된 판단만** 채점한다. 승인 못 받은 전략은 실전 표본이 쌓이지 않으므로 영영 승인될 수 없다.
- 시험한 변형이 둘 이상(`trial_count > 1`)이면 백테스트가 통과해도 차단 사유가 붙고, `approval()`은 차단 사유가 하나라도 있으면 곧바로 `insufficient`(표본 부족)로 돌려준다. 차단 문구는 "새 미래 검증 전에는 강한 승인이 불가하다"인데, 그 **미래 검증을 하는 경로가 코드에 없었다.**

섀도 기록이 그 미래 검증 역할을 한다. 등록한 시점 **이후**에 쌓인 값만 쓰므로 과거 데이터를 보고 전략을 고른 영향이 들어가지 않는다.

## 무엇이 섀도 판단인가

아래를 모두 만족할 때만 판단 행에 `shadow`를 붙인다.

| 조건 | 이유 |
| --- | --- |
| 정량 후보이고 승인 못 받아 매수하지 않음(검증 부족·실패·최근 악화) | 이미 산 것은 실제 매수 통계로 센다 |
| 현재 신호 조건과 가격 조건이 모두 충족 | 신호가 꺼진 날은 전향 관측이 아니다 |
| 현재 숫자가 검증 원문과 연결되고, 가격이 신선하고, 무효화 조건이 발생하지 않음 | 읽을 수 없는 신호를 관측으로 세지 않는다 |
| 수익 정의·생존편향 같은 비교 정의 차단이 없음 | 비교 자체가 정의되지 않으면 전향 기록으로도 고칠 수 없다 |
| **사전 등록된 같은 정의의 전략**이고 적용 대상(자산·상품·비교 시장)이 같음 | 규칙이 결과보다 먼저 고정되었음을 보장한다 |

섀도 행의 `amount_krw`는 항상 `"0"`이고 행동은 매수가 아니다. 배분(`allocate`)은 매수 행동만 보므로 섀도 행은 신규 자금·현금 계산에 들어가지 않는다. 기록할 때(`record`) 이 불변식을 다시 검사한다.

구분은 두 가지다.

- **승격 후보**(`candidate`): 백테스트가 표본 부족이거나 시험 변형 수 때문에 막힌 경우. 전향 기록이 문턱을 넘으면 승격할 수 있다.
- **대조군**(`control`): 백테스트에서 실패했거나 실전 경고로 악화된 경우. 기록은 쌓지만 이 장치로는 **승격하지 않는다.** 승인 문턱이 정보를 담고 있는지 점검하는 용도다. 대조군 결과를 보고 문턱을 낮추지 않는다. 문턱을 바꾸려면 새 규칙 버전과 새 전향 기간이 필요하다.

범위 밖(의도적): 승인됐지만 재무 제약·자금 한도 때문에 못 산 판단은 섀도로 기록하지 않는다. 같은 종류의 문제(실전 표본이 안 쌓임)이지만 이번 요청 범위가 아니다.

## 사전 등록

```bash
python -m investment_research invest strategy register my_library.json --journal reports/investment_journal
python -m investment_research invest strategy list --journal reports/investment_journal
python -m investment_research invest strategy discard my_strategy v1 --reason '이유' --journal reports/investment_journal
```

- 라이브러리 파일은 `investment-strategy-library-v1`이고 `entries` 배열에 **testable**(전략 정의 전체·적용 대상·출처 구분) 또는 **untestable**(지금은 시험할 수 없는 후보와 이유·필요한 것)을 적는다. 시험 불가 후보도 기록해 두어야 "성공한 것만 보고"하지 않는다. 시험 불가를 통과로 세지 않는다.
- 라이브러리 등록은 전부 또는 전무다. 한 항목이라도 검증에 실패하면 아무것도 등록하지 않는다(먼저 복사본에서 같은 검사를 돌린다).
- 등록 시각은 **이 컴퓨터의 시계**다. 명령줄에서 바꿀 수 없다. 같은 정의의 재등록은 아무 일도 하지 않고 처음 시각을 유지한다. 정의가 바뀌면 새 버전과 부모 해시가 필요하다.
- 등록·폐기·판단 기록은 `chain.jsonl`의 **해시 체인**에 연결한다. 항목을 지우거나 고치거나 순서를 바꾸면 체인이 깨져 `read_chain`·`invest review`가 거부한다. 판단 결과에는 그 시점의 체인 머리 해시를 남긴다.
- **시험 후보 수 K**는 체인에서 센다(폐기한 전략 포함, 시험 불가 후보 제외). 직접 적는 값이 아니다. K를 줄이려고 저널을 나누지 않는다. 저널 하나가 하나의 시험군이다.
- 출처 구분(`학술·공식`, `실무자 공개 자료`, `커뮤니티·SNS 가설`, `자체 가설`)은 근거의 무게가 아니라 **출처의 기록**이다. 어느 구분이든 가설이다.

## 승격 문턱

문턱은 **등록할 때 전략과 함께 고정**한다(`promotion_rule`). 기본 숫자는 계획 정책의 기존 값을 그대로 쓴다: 독립 성숙 표본 `minimum_historical`(20), 최근 `minimum_live`(10). 나중에 계획의 정책 숫자를 바꿔도 이미 등록한 전략의 문턱은 낮아지지 않는다.

같은 전략의 **독립**(보유기간이 겹치지 않음) 성숙 섀도 표본이 정해진 개수 N에 **처음 도달했을 때 한 번만** 판정한다. 통과 조건은 모두 만족해야 한다.

1. 처음 N개의 시장 대비 평균 초과수익의 **보정한 신뢰 하한이 0보다 큼**
2. 그 N개 중 최근 10개의 시장 대비 평균 초과수익이 0보다 큼

- 보정한 하한 = 재추출(부트스트랩) 분포의 `0.025 ÷ K` 분위수. K=1이면 기존 95% 하한과 같다. 재추출 횟수는 `max(10000, 800×K)`이고, 그 꼬리를 풀 수 없으면 하한을 만들지 않고 통과시키지 않는다.
- K는 **판정 시점(N번째 표본이 성숙한 시각)까지 등록된 전략 수**다. 그 뒤에 등록한 전략은 이 판정을 더 엄격하게 만들지 않는다. 그 시점 이전에 이미 등록했다면 폐기해도 센다.
- 한 번만 판정하는 이유: 새 표본이 쌓일 때마다 다시 검사하면 우연한 호조가 어느 순간 기준선을 넘는다(관찰할 때마다 기회가 늘어난다). N번째 이후의 표본은 승격이 아니라 경고·철회에만 쓴다. 놓치면 새 버전과 새 전향 기간으로 다시 시작한다.
- 통과해도 `승격 후보`만 승격한다. 실제 판단에서 `shadow_promoted`가 되어 **C등급(신규 자금의 5% 상한)까지만** 매수한다. A·B등급으로 올라가는 길은 열지 않았다.
- 철회: 판정 뒤에 성숙하는 섀도 표본이 나빠져 상태가 `경고`·`폐기 후보`가 되면 자격을 철회한다. 승격 뒤 실제 매수 결과가 `경고`가 되면 기존 규칙대로 매수를 중단한다. 실전 경고는 승격보다 우선한다.

### 시간이 걸린다

독립 표본은 보유기간마다 하나씩만 쌓이므로 N=20이면 최소한 이 정도다(신호가 꺼지는 기간이 있으면 더 길다). 이것은 산술이고 관측이 아니다.

| 전략의 보유기간 | 독립 표본 20개에 필요한 최소 기간 |
| --- | --- |
| 1개월 | 약 20개월 |
| 3개월 | 약 5년 |
| 6개월 | 약 10년 |
| 1년 | 약 20년 |

그래서 현실적으로 승격 후보는 1개월 보유 전략 위주가 된다. 긴 보유기간 전략은 섀도 기록으로 경고·폐기 후보를 알려 주는 쪽이 더 현실적이다. 1주~1년 결과는 모두 기록하지만 승격 판정은 전략의 등록된 보유기간 하나만 쓴다(기간을 섞지 않는다).

## 다중 검정: 무엇을 택했고 왜

후보를 많이 시험할수록 우연히 통과하는 전략이 섞인다. 요청서의 세 선택지(시도 횟수 공개, 더 높은 문턱, 섀도 기간 요구) 중 **섀도 기간 요구**를 택했다.

- *시도 횟수 공개*만으로는 우연 통과를 줄이지 못한다. 공개는 필요조건이라 K·시험 불가·폐기 목록으로 남기지만 그것만으로 방어하지 않는다.
- *과거 백테스트의 문턱을 더 높이는 것*은 실제 시도 횟수를 알아야 보정할 수 있는데, 후보를 고르는 사람(과 이 도구를 만든 사람)이 이미 과거 결과와 문헌을 알고 있다. 예시 계획도 "적용 대상 선택은 BTC 과거를 아는 상태에서 이뤄졌으므로 완전한 사전 등록은 아니다"라고 스스로 적는다. 이미 본 데이터 위에서는 몇 번을 시도했는지 정직하게 셀 수 없다.
- *전향 기록*은 등록 이후의 자료만 쓰므로 시험군이 확정되고(K를 체인에서 센다) 그 K로 보정할 수 있다. 그래서 보정은 전향 검정에만 건다.

그리고 한 번만 판정하는 규칙이 연속 관찰에 의한 우연 통과를 막는다. 보정은 보수적이다(Bonferroni 방식이라 후보끼리 상관이 높으면 필요 이상으로 엄격하고, 상관이 있는 후보를 독립 증거로 세지도 않는다). 표본이 20개 안팎이면 부트스트랩 하한 자체도 근사이며 구조 변화를 보장하지 않는다.

## 스키마 변경과 영향 범위

| 위치 | 변경 | 호환 |
| --- | --- | --- |
| `decision_data.VERSION` | 기본 판단 규칙이 `investment_cycle_v4` | v1~v3 저장 실행은 그 버전 그대로 재현한다 |
| 판단 행 | v4에만 선택 필드 `shadow`(`tracked`, `track`, `registration_sha256`, `amount_krw`) 또는 추적하지 못한 이유 | `shadow`가 없는 행은 이전과 같다 |
| 판단 결과 | v4 + 등록부 연결 시 `strategy_registry`(체인 머리 해시, 시험 후보 수) | 없으면 키 없음 |
| 판단 입력 | 스냅샷에 등록부 보기(`strategy_registry`)를 저장 | 재현에 저널이 필요하지 않다 |
| 저널 | `chain.jsonl`, `registrations/<sha>.json` 추가. `decisions/`·`strategies/`·`reviews/`는 그대로 | v1~v3 판단은 체인에 없어도 된다. v4 판단은 반드시 체인에 있어야 한다 |
| 사후 평가 | 섀도가 있을 때만 `shadow_outcomes`, `shadow_limitation`, `strategies['…/shadow_real|shadow_synthetic']` | 섀도가 없는 저널의 평가 결과는 이전과 바이트 단위로 같다 |
| `backtest.py` | `period_results`·`forward_verdict`·`lower_confidence_bound` 추가, `approval`은 같은 결과를 돌려줌 | v1~v3 재현 테스트가 지킨다 |
| 보고서 | 섀도가 있을 때만 "섀도 기록" 구역 | 섀도가 없는 보고서는 이전과 같다 |
| `ask --journal` | 같은 등록부 보기를 입력에 저장 | 저널이 없으면 섀도 없음 |

v4의 행동·등급·금액은 승격된 전략을 빼면 **v3와 완전히 같다**(여러 시나리오로 비교하는 테스트가 있다). 여러 변형을 시험한 전략의 백테스트 실패가 보유 자산의 `비중 축소 검토`로 번지는 변화는 일부러 만들지 않았다. 대조군 분류만 별도 판정(`forward_verdict`)으로 한다.

## 한계 (하지 않거나 못 하는 것)

- 섀도 결과는 **다음 관측 진입을 가정한 평가**다. 체결·슬리피지·세금이 없고 금액 0이라 시장 충격도 시험하지 않는다.
- 판단을 **실행한 시점**의 신호만 기록된다. 실행하지 않은 주의 신호는 표본에 없다. 실행 주기가 불규칙하면 표본이 줄고, 신호가 켜졌을 때만 골라 실행하면 치우친다(꺼진 때를 건너뛰는 것은 무해하지만 켜진 때를 건너뛰면 아니다).
- 체인은 **변조 흔적**을 남기지만 막지는 못한다. 디렉터리 전체를 다시 쓸 수 있는 사람은 체인도 다시 쓸 수 있고, **가장 최근 판단 파일과 그 체인 줄을 함께 지우는 것**은 감지하지 못한다. 중요하면 체인 머리 해시를 저널 밖에 보관한다.
- 등록 시각은 이 컴퓨터의 시계다. 다른 사람에게 그 시각을 증명하지 못한다.
- 한 저널은 하나의 시험군이다. 서로 다른 자산·전략도 K에 함께 센다. 상관이 높은 후보가 여럿 통과해도 독립 증거 여러 개로 세지 않는다.
- 승인됐지만 자금 제약으로 못 산 판단은 섀도로 기록하지 않는다.
- 세율·계좌 요건·상품 접근 요건은 코드에 넣지 않았다([전략 가설 조사](strategy-hypotheses.md)에 출처와 확인일만 기록).
