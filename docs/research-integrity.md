# 리서치 신뢰성과 검증 규칙

현재 [투자 판단 순환](investment-cycle.md)에 아래 시점·정의·비교 규칙을 실행 코드로 적용했다. 데이터 구조와 원문 일치 검사가 경제적 인과나 미래 수익을 자동 증명하지 않는다는 경계는 유지한다. 검토된 가설·시점 보장 이력·독립 검증·실제 현재 원문이 함께 있을 때 결정적 승인 정책으로 행동을 계산한다.

검증 대상은 가격·계산뿐 아니라 현재 시장을 설명하는 거시 자료, 기업·산업의 사업 근거, 공개된 시장 서사, 사용자에게 적용할 조건이다. 좋은 리서치는 정보량이나 확인된 지표 수가 아니라 질문에 관련된 주장, 반대 근거, 대체 투자기회와의 비교가 얼마나 타당한지로 평가한다. 합성 오프라인 브리프에 더해 실제 공개 source의 명시적 획득·보존·replay·좁은 주장 검증과 실제 거시 원관측·시점 선택·결정적 변환·한국어 snapshot이 구현되어 있다. 원문 의미·경제적 일반 주장·현재 투자 매력을 자동 판정하는 기능은 없다. 현재 경계는 [출처 획득·검증 안내](source-acquisition.md)와 [거시 MVP 안내](macro-mvrs.md)를 따르며 백테스트와 미구현 자산별 방법은 도입할 때 아래 규칙을 적용한다.

## 1. 위험은 서로 다른 지점에서 발생한다

[네 연구 모드](research-modes.md)는 독립 진입점이지만 동일한 근거·시점·출처·UNKNOWN 규칙을 공유한다. 모드 선택이나 계획 형식의 유효성은 경제적 판단의 검증이 아니다. 질문에 필요하지 않은 전체 Scan, 동일 지표의 강제 적용, 미확인 보유정보로 전체 포트폴리오 안전성 주장도 품질 오류다. 지정 대상의 직접 연구에서 이전 후보 선정이 없다는 이유로 분석을 막지 않는다.

| 오류 | 예방 경계 | 실패 시 행동 |
| --- | --- | --- |
| 출처 없는 숫자·표본수 | 근거 ID와 계산·출처 참조, 정형 수치 렌더링 | 수치와 그 수치를 전제로 한 주장 거부 |
| 잘못된 단위·통화·기간 | 명시적 자료 계약과 적용 조건 검증 | 해당 계산 중단 |
| 결정적이지만 틀린 계산 | 독립 검산, 정의 문서, 성질 테스트 | 방법을 수정하고 영향을 받은 실행을 새로 생성 |
| 공개 전 정보를 사용 | 정보 기준 시점과 자료 버전 검증 | 해당 과거 실험 차단 |
| 근거 없는 해석·과장 | 주장 유형·참조·논리 검토, 사용자 검토 | 해석을 제거하거나 불확실한 가설로 표시 |
| 데이터가 부족한데 강한 결론 | 표본·의존성·구간·품질 공개 | 일반화·비교 우위 주장 제한 |
| 다른 성격의 자산·수익을 직접 순위화 | 비교 프레임과 비교 가능 상태 | 해당 비교를 제한하거나 차이를 별도로 설명 |
| 반복된 커뮤니티 주장을 사실로 취급 | 주장 발견과 사실 검증 분리, 원출처·중복 확인 | 미검증 서사로 남기고 투자 근거로 승격하지 않음 |
| 시장 기회를 사용자 적합성으로 자동 연결 | 사용자 정보 버전·제약·미확인 입력 확인 | 개인 적합성 판단의 적용 범위를 제한 |
| 외부 문서의 도구 호출 지시 | 신뢰 경계와 읽기 전용 제한 | 지시를 실행하지 않고 데이터로 취급 |

스키마와 체크섬은 각각 구조와 동일성을 확인한다. 자료의 경제적 의미, 원본의 정확성, 미래 예측력을 자동 보증하지는 않는다.

[Source Discovery & Freshness MVP](source-discovery.md)는 이 규칙을 수집 앞단에도 적용한다. 질문의 evidence need를 먼저 정하고 검색/목록의 후보를 실제로 열어 본 뒤 원문·관측 시각·정의가 확인된 자료만 기존 pipeline에 승격한다. 검색일·footer·획득일로 과거 관측을 최신화하지 않고, 같은 source의 신판이 미완성/미확보이면 구판을 현재 자료로 조용히 대체하지 않는다. primary라는 이유만으로 다른 정의의 상품 AUM을 BTC ETF 순유입처럼 사용하지 않는다. source 선택·거절·판본·gap과 원문/선택의 재현 한계를 기록하며, 새 숫자 전사 확인도 경제적 가설의 support를 자동 만들지 않는다.

## 2. 출처, 근거, 주장을 구분한다

`SourceRecord`는 정보가 어디서 왔는지, `EvidenceRecord`는 그 출처에서 무엇을 확인했는지, `ResearchClaim`은 그 근거로 무엇을 주장하는지 기록한다. 실제 자료는 SourceSpec·Snapshot에서 기존 타입으로 연결되며 optional provenance에 보존 자료·구절 일치·최신성을 기록한다. 문서 하나에 여러 주장이 있으면 따로 평가한다. 인용 링크가 있다는 사실은 주장의 정확성이나 해석의 타당성을 보증하지 않는다.

시계열의 관측일은 값별 원문 행에 속한다. 최신 시리즈 날짜·공개일·획득일을 과거 값에 복사하지 않는다. 월/분기 기간 말일 표기와 실제 일별 관측을 구분하고, 날짜 미확인·기간 불일치 값은 변화·trend·반복 Scan 비교에 사용하지 않는다. 날짜 버그 수정은 새 실행과 별도 대조 기록으로 남기며 과거 artifact를 조용히 고치지 않는다. [구현·날짜 의미](source-acquisition.md#값별-observation-date-보존)를 따른다.

원자재의 과거 총수익만으로 현재 기회를 주장하지 않는다. 같은 기간·통화·수익 유형의 하위 그룹 자료와 명확한 구성일을 확인한다. 중간 시점의 과거 비중에 전체 YTD 성과를 곱해 공식 기여율처럼 표현하지 않는다. spot/excess/total return, 실현 교체 효과·담보 이자, 지수와 상품 NAV 총수익을 구분하며 미확보 분해는 미확인으로 남긴다.

### Source hierarchy

| 우선순위 | 출처 종류 | 검토할 한계 |
| --- | --- | --- |
| 1 | 공식 원자료, regulatory filing, 정부기관, 거래소 | 개정·공개 지연·정의·범위, 제출자가 보고한 내용인지 확인 |
| 2 | 기업 공식 자료, investor relations, earnings call | 경영진 주장·가이던스와 실제 달성 결과를 구분; 이해관계 확인 |
| 3 | 신뢰할 수 있는 금융 데이터 제공자 | 원자료·조정·추정 방법·당시 버전·라이선스 확인 |
| 4 | 신뢰할 수 있는 언론과 전문 research | 인용 원출처·편집·가정·보고 시점 확인 |
| 5 | 전문가 의견 | 전문 영역·이해관계·검증 가능한 논리 확인 |
| 6 | 커뮤니티, social media, 개인 의견 | 비대표성·선택편향·조작·주장 미검증을 기본 한계로 공개 |

이 순서는 중요한 주장에 대한 검증 경로를 정하는 기본값이다. 등급이 높은 문서도 예측·의견을 담을 수 있고, 공식 수치도 해당 질문에 오래되거나 정의가 맞지 않을 수 있다. 출처 등급, 주장 검증 상태, 시점·관련성·품질을 별도 필드로 남긴다. 낮은 등급에서 발견한 중요한 주장은 가능한 상위 출처로 확인하되, 원자료가 없다는 이유로 내용을 만들어 채우지 않는다.

### 최소 기록

- **출처**: 안정적인 출처 ID, 요청·canonical URL 또는 원본 참조, 발행 주체·제목, 자료 종류·등급, 발행·관측·유효 시점과 실제 획득 시각, 관할·주제, content type·접근 방법, 원출처 관계, 접근·저장·인용 권한. 미확인 날짜는 그대로 남긴다.
- **비수치 근거**: 문서 버전, 확인 가능한 구절·표·페이지·영상 시점 등 위치, 필요한 맥락, 해당 주장의 대상·기간·범위. 요약·번역을 원문과 구분하고 보존이 제한되면 허용된 참조와 검증 한계를 남긴다.
- **수치 근거**: 검증된 관측·계산 ID, 단위·통화·정의·기간, 입력·방법 버전, 불확실성. 원문 수치를 옮기는 과정도 검증한다.
- **주장**: 사실·계산·해석·가정·가설 유형, 지지·반대·배경 근거 ID, 논리 연결, 적용 범위, 의존 전제, 확인 상태, 미확인 항목, 무효화·재조사 조건. `context_ids`는 배경 자료이며 지지·반대나 높은 결론 강도의 근거로 자동 변환하지 않는다.
- **검증 기록**: 어떤 자료와 비교했는지, 일치·불일치 이유, 확인 시점, 확인하지 못한 범위. 재검증하면 원기록을 덮어쓰지 않는다.

사실 주장 확인 상태는 `supported_within_scope`(한정된 범위에서 확인), `partially_supported`(일부만 확인), `contradicted_within_scope`(동일한 범위의 자료와 모순됨), `disputed`(자료가 상충함), `unverified`(아직 확인하지 못함), `not_verifiable`(현재 자료·방법으로 확인 불가)를 구분한다. 해석의 검토 여부·검토자·시점·범위·검토 기록과는 별도로 관리한다. 사실을 확인해도 그 해석을 채택했다는 뜻은 아니다. 이 상태는 투자 아이디어의 진실·거짓이나 미래 수익 여부를 자동 결정하지 않는다. 확인 실패는 거짓의 증거가 아니며, 일부 조건에서 확인된 주장을 범위 밖으로 일반화하지 않는다.

합성 경로의 상태는 fixture 작성자의 명시적 검토 기록이다. 실제 source 경로에서는 획득 성공·구절 존재·지원 수치의 추출·주장 상태·해석 검토를 구분한다. 코드는 확인/일부 확인 주장에 적격 비커뮤니티 지지 근거, 반박 주장에 적격 반대 근거, 상충 주장에 양쪽 근거와 검토 기록이 있는지 검사한다. 원문 의미와 논리적 함의를 자동 판정하지 않는다. 사실 확인된 근거라도 해석이 `pending`/`rejected`이면 투자상의 지지·반대 근거로 채택하지 않는다. 커뮤니티 발언과 일부 확인·미확인 근거도 보류 이유를 남긴다. 기회비용·재검토 설명의 모든 참조가 적격일 때만 검토된 조건부 해석으로 표시한다.

현재 `numeric_equality_v1`은 지원하는 원문 추출과 동일한 measure·단위·기간·통화·scope·adjustment를 가진 좁은 수치를 비교한다. 예제의 Fed 원문에 있는 1/2 percentage point 인하를 50 basis points로 변환하는 확인은 그 정책 결정의 수치에 한정된다. 인하의 이유·경기 전망·투자 성과까지 검증한 결과가 아니다. assertion의 adjustment를 생략하면 참조 구절 정의를 상속하며 별도의 조정 가정을 확인했다고 표현하지 않는다.

`reviewed_links_v1`은 명시한 사례 검토 기록의 상태를 자료·범위와 함께 보존한다. 기록이 있다는 사실을 실제 사용자의 승인, 독립 전문가 검토, 자동 사실 판정으로 설명하지 않는다. 확인·일부 확인에는 검토된 비커뮤니티 근거가 필요하며 커뮤니티 내용만 있는 주장은 미확인으로 남긴다. 필요한 source를 확보하지 못했거나 구절이 없으면 성공 근거를 만들지 않고 관련 주장과 누락 참조를 미확인·진단으로 보존한다.

HTML 구절 일치는 정규화된 공개 텍스트에 해당 구절이 있다는 확인이다. HTML `locator`는 설명용 레이블로, 지정 문단·DOM·표 위치가 실제로 맞는지 검증하지 않는다. 지원하는 JSON 구절은 지정 필드로 연결한다. 여러 출처의 일치·출처 위계·구절 존재도 금융 해석의 진실 점수가 되지 않는다.

거시 경로는 원관측과 변환 입력을 기존 `EvidenceRecord`, 계산을 같은 값·단위·입력 ID의 `MetricResult`, 좁은 계산 사실을 `ResearchClaim`으로 연결한다. 결정적 공식 필드 파싱·계산의 검토 기록은 독립 전문가나 사용자의 투자 해석 승인과 구분한다. 보고서는 evidence/metric의 값·단위·원문 판본 참조가 결과와 맞지 않으면 거부한다. 금리·물가·환율의 가능한 전파 경로는 추가 자료와 검토가 필요한 해석 후보이며 계산 사실과 같은 수준으로 확정하지 않는다.

기업 자료에서 경영진이 성장 전망을 제시했다면 “경영진이 해당 전망을 발표했다”는 확인할 수 있어도 “그 성장이 실현된다”는 별도 가설이다. 마찬가지로 “여러 게시물이 재고 부족을 주장한다”는 공개 발언의 관측과 “공식 재고가 역사적으로 부족하다”는 사실 주장은 서로 다르다.

## 3. 서로 다른 근거의 결합과 비교

거시, 펀더멘털, 정량, 커뮤니티 연구는 서로 다른 질문에 답한다. 하나의 점수로 합산하지 않고 `ResearchBrief`의 질문과 `ResearchPlan`의 검토 범위에 필요한 근거만 연결한다.

| 연구 관점 | 주로 확인할 내용 | 단독으로 증명하지 못하는 것 |
| --- | --- | --- |
| 거시 | 금리·물가·성장·정책·유동성·신용이 특정 노출의 현금흐름·할인율·위험에 전달되는 경로 | 거시 지표 방향만으로 자산의 상승이나 적정 비중 |
| 펀더멘털 | 사업·산업·수급·현금흐름·재무·가격·촉매와 위험의 연결 | 낮은 배수만으로 저평가, 경영진 가이던스만으로 성장 실현 |
| 정량 | 일관된 정의의 관측 비교, 계산, 민감도, 분포, 필요한 과거 가설 평가 | 과거 패턴만으로 인과나 미래 확률 |
| 커뮤니티·서사 | 참여자가 중요하게 여기는 논점·우려·새 가설, 과도한 낙관·비관의 관측 | 인기도·반복 횟수만으로 사실·시장 전체 의견·투자 우위 |

결합할 때는 “어떤 관측 → 어떤 전달 경로와 가정 → 어떤 투자상의 의미”를 명시한다. 예를 들어 금리 변화의 사업 영향, 현재 가격에 반영됐을 가능성, 경쟁하는 설명은 각각 다른 주장으로 검토한다. 근거가 같은 기관 자료를 재인용했거나 같은 자료에서 계산됐으면 독립된 확인으로 세지 않는다. 상충 자료는 선택적으로 버리지 않고 정의·기간·개정·대상 차이를 확인하며, 해소되지 않으면 강한 결론을 유보한다.

### Cross-asset 비교 계약

`ComparisonFrame`은 비교 목적, 사용자 기준 통화, 투자·평가 기간, 수익 정의, 비용·세금 포함 범위, 접근 가능한 상품, 유동성·보유 제약, 위험의 종류, 불확실성과 비교 가능 상태를 고정한다. `MarketContext`는 이 질문과 연결되는 거시 항목·기준 시점만 포함한다. 하나의 불완전한 시장 스냅샷을 모든 투자 아이디어에 공통 근거로 강제하지 않는다.

- 국채 수익률, 현금 이자, 주식의 과거 평균, 추정 미래 수익률은 정의가 다르다. 직접 수익률 순위에 넣지 않는다.
- 필요하면 동일 보유 기간의 시나리오·현금흐름·손실 경로로 비교하되, 자료와 방법이 지원하는 범위만 산출한다. 모형 결과는 관측 결과와 구분한다.
- 명목/실질, 원 통화/KRW, 세전/세후, 총수익/가격수익, 약정 수익/시장가격 위험을 맞추거나 차이를 표시한다.
- 실시간 가격이 없는 부동산은 적은 관측 횟수나 가격 평활화가 위험을 숨길 수 있다. 가격 변동성만으로 주식보다 안전하다고 판단하지 않는다.
- 현금 대기에도 이자·물가·향후 선택권·놓칠 수 있는 기회를 검토한다. 결론 유보만으로 현금의 상대 우위를 확정하지 않는다.
- 비교 불가 또는 부분 비교는 정상 상태다. 필수 비교 전제가 없으면 “다른 대안보다 유리하다”는 주장을 차단하고 가능한 차이만 설명한다.

사용자 적합성은 시장 주장과 별도로 검토한다. `ProfileSnapshot`의 기준 시점·버전과 유동성 필요, 부채, 기존 노출, 주택 계획, 손실 감당 능력·감수 의향 등을 연결한다. 필요한 개인 조건이 `unknown`이면 조건부 해석과 추가 질문을 제시한다. 나이·소득·장기 투자 의향만으로 배분 비중이나 레버리지 허용을 생성하지 않는다. 기존 보유자산의 위험 집중은 지원되는 노출 자료의 범위에서만 설명하며 누락 보유자산을 없다고 간주하지 않는다.

## 4. 커뮤니티·social research 검증

커뮤니티 연구의 산출물은 검증할 주장, 확산 중인 서사, 참여자의 우려, 추가 조사 질문이다. 그 자체가 검증된 금융 사실이나 매매 신호는 아니다. 현재 시장을 대표하는 모집단을 알고 있지 않으면 관측한 채널·기간·검색 조건 안에서만 표현한다.

1. 공개적으로 접근 가능한 자료와 이용 조건을 확인한다. 접근 제한 우회, 허가 없는 수집·재배포를 전제로 설계하지 않는다. 불필요한 계정 식별자·개인정보를 수집하거나 외부 LLM에 전달하지 않는다.
2. 채널, 검색 기준, 수집 시간·기간, 표본 선택·제외 기준, 언어·지역 범위를 기록한다. 검색·추천 알고리즘과 삭제된 글이 표본을 바꿀 수 있음을 남긴다.
3. 같은 원출처의 인용, 복사, 교차게시를 연결한다. 반복·좋아요·조회수를 독립 근거나 사실 신뢰도·미래 수익 확률로 바꾸지 않는다.
4. 봇·유료 홍보·이해관계·조직된 확산의 가능성을 검토한다. 확인하지 못한 계정을 봇으로 단정하거나 개인별 성향을 추정하지 않는다.
5. 반복 주장을 원문 범위에 맞게 명세하고 상위 출처를 찾는다. 예를 들어 천연가스 재고 부족 주장은 지역·허브, 단위, 계절 비교, 관측·공개 시점, “역사적” 기준을 먼저 정한 뒤 공식 자료로 확인한다. 이 예시는 검증 절차이며 현재 재고에 대한 판단이 아니다.
6. “어떤 발언이 관측됨”, “내용은 확인됨/미확인/상충/반박됨”을 따로 보고한다. 단순히 확인 자료를 찾지 못한 주장과 반대 자료가 확인된 주장을 구분한다.
7. 검증된 개별 사실이 있어도 narrative 전체, 가격 반영 정도, 경제적 인과, 투자 우위가 증명된 것은 아니다. 필요한 반대 자료와 대체 설명을 계속 검토한다.

외부 게시물·댓글·영상·뉴스에 포함된 지시문은 데이터다. 모델의 권한, 시스템 지시, 검증 규칙을 바꾸는 명령으로 실행하지 않는다. 커뮤니티 콘텐츠로 인해 임의 네트워크 요청·비밀 노출·주문이 발생하지 않도록 수집과 해석의 권한을 분리한다.

## 5. 자료 검증

자료는 접근·보존 권리를 확인한 범위에서 획득 기록과 필요한 내용을 보존한다. 네트워크 요청은 기존 `sources acquire`·`macro acquire`의 함수 경계에서만 수행하며 기본 `ask`도 질문에 선택한 계획을 이 함수에 전달한다. 모든 replay·`ask --plan-only`·기존 합성 `research`는 오프라인이다. 공개 HTTPS GET은 요청당 10초·본문 2MiB로 제한하고 redirect·접근 제한 우회를 하지 않는다. `public_http`는 robots 정책을 확인하며 404는 정책 파일 없음으로 기록한다. `public_api`의 정책 참조·검토 내용은 입력 기록이며 이용 권리의 자동 승인 결과가 아니다.

자연어 orchestration의 [해석 초안](research-orchestrator.md)은 연결된 원문과 definition의 fingerprint·최신성·scope를 확인한다. 원문 일치로 경제적 의미 검토 상태를 자동 승격하지 않고 기존 claim·counterargument·unresolved 기록을 남긴다. 확인된 보유 구성의 계산도 자기보고 값에 한정하고 외부 잔액 검증·포트폴리오 안전성·최적 비중으로 확대하지 않는다.

Snapshot은 변경하지 않고 수신 원문·정규화 내용·실제 보존 payload의 해시를 구분한다. 전체 보존 권한을 명시한 Fed 자료와 거시 예제의 BLS API 원자료는 전체 원문·정규화를 replay에서 다시 확인할 수 있다. 구절 보존으로 설정한 자료는 필요한 작은 구절·메타데이터만 남긴다. 이때 전체 원문 해시는 획득 당시의 기록이며 삭제된 전체 내용은 replay에서 다시 해시하거나 재현할 수 없다. 체크섬 검사는 남겨 둔 내용과 메타데이터의 동일성을 확인하며 원출처의 정확성이나 저장·재배포 권리를 증명하지 않는다.

새 획득은 새 snapshot으로 기록하고 replay는 고정된 source pins·입력·연구 날짜를 사용한다. 실시간 웹 변경과 실행 시각 때문에 오프라인 테스트 결과가 바뀌지 않는다. URL 접근·timeout·파싱·정책·구절 변경 실패는 획득 상태·진단으로 남기며, 실패한 source를 정상 근거로 대체하지 않는다.

### 현재성 및 검토 날짜

발행일·관측일·유효 시점·획득 시각은 서로 다르다. 발행일 미확인을 획득 시각으로 채우지 않고, 현재 획득한 과거 문서로 당시의 실제 이용 가능성을 증명하지 않는다. 현재 replay는 증명하지 못한 `available_at`을 미확인으로 둔다.

`sources replay`의 출처 최신성은 고정된 연구 날짜, 유효·관측·공개 시점, source별 허용 나이로 평가한다. 알려진 미래 날짜가 있으면 발행일 미확인보다 `future`가 우선한다. `stale`·`unknown`·`future` 근거는 현재 투자상의 채택을 유보한다. 오래되거나 날짜 일부가 미확인인 자료도 보존 원문에 적힌 과거의 좁은 사실을 범위 내에서 확인할 수 있으며 이를 현재 시장 사실로 바꾸어 부르지 않는다. 거시 경로는 아래와 같이 관측별 이용 가능 하한과 나이를 확인하며, 기준 시점 이후 판본을 이전 기준 시점의 사실 확인 근거로 승격하지 않는다.

근거의 기록된 검토 날짜는 관측·획득보다 앞설 수 없다. 주장의 기록된 검토 날짜는 지지·반대·배경·연결 서사·숫자 assertion에 참조된 근거의 분석·검토보다 앞설 수 없다. `pending`이어도 날짜를 기록했다면 같은 경계를 검사한다. 날짜만 있는 검토 기록으로 같은 날짜 안의 상세 시간 순서까지 증명하지 않는다.

### 거시 시계열과 당시 이용 가능성

`SeriesDefinition`은 headline/core, index/상승률, 계절조정 여부, 명목/실질·만기, 정책/시장금리, 환율 방향을 구분한다. canonical ID의 정의와 source·단위·빈도·조정·통화 조건이 바뀌면 기존 시계열에 합치지 않는다. 현재 어댑터는 BLS의 지정 CPI-U NSA index와 Fed의 지정 Treasury·USD/KRW 열·메타데이터를 확인한다. Treasury 원문 `Currency: NA`는 비율 단위이며 정의의 USD 통화 맥락과 별개다.

월별 관측일은 해당 월의 기간 라벨이다. 과거 관측일에 현재 수정 값을 연결해 당시의 지식으로 소급하지 않는다. 공개·vintage·revision·known-at 또는 유효 시점이 cutoff 이후인 판본은 제외한다. 공개 시각을 모르거나 개정 판본의 당시 이용 가능성을 입증하지 못하면 획득 시각을 보수적인 이용 가능 하한으로 삼되, 실제 공개 시각을 그 값으로 채우지 않는다. 현재 어댑터의 `retrieved_snapshot` vintage는 시스템이 확보한 판본이며 공식 과거 vintage의 증명이 아니다.

예제의 현재 CPI는 공식 release의 관측월·지수·발표 시각 구절을 API 값과 대조하고 America/New_York의 발표 시간을 UTC로 연결한다. 일치한 한 관측의 release만 확인하며 나머지 월의 공개·개정 이력을 추정하지 않는다. release와 API를 확보한 순간보다 known-at을 앞당기지 않는다. 발표 구절·필드가 바뀌거나 값이 상충하면 정상적인 교차 확인 근거로 쓰지 않는다.

`--previous-pins`는 이전에 확보한 판본을 새 pins에 추가한다. 같은 관측 기간의 여러 판본을 보존하고 cutoff 조건을 통과한 마지막 판본을 선택한다. 같은 이용 가능 판본의 충돌 값은 임의 선택하지 않는다. 현재 파일만으로 과거 당시 값을 확인할 수 없는 질의는 미래 판본을 제외하고 부족·차단을 보고한다. 합성 revision 테스트가 통과했다고 실제 전체 과거 revision 이력을 확보했다고 표현하지 않는다.

최신 선택 관측이 결측이면 이전 값으로 대체하지 않는다. 신선도는 기준 시점과 관측 기간의 계획상 허용 나이를 사용하며 `stale`은 현재 핵심 요약에서 제외하고 과거 기록으로 보존한다. 공개 calendar가 없으면 가장 최근에 있어야 할 기간이나 발표 지연을 완전히 판정하지 못하므로 그 한계를 공개한다. 날짜 cutoff의 UTC 일말과 timezone을 지정한 순간은 다르며 저장·보고서에 기준 시점을 명시한다.

### 실제 Opportunity Map의 검토 경계

현재 [Broad Scan](opportunity-map.md)은 source 구절·거시 계산·사용자 자기보고와 UNKNOWN을 연결하지만 경제적 의미·투자 매력의 자동 확인은 하지 않는다. 순위·점수·예상 수익률·비중을 만들지 않는다. 자료가 fresh이고 비커뮤니티 원문이 일치하면 조사 질문의 단서로 사용할 수 있으며 해석은 pending 초안으로 유지한다. 연구 우선순위는 투자 추천과 별도다. 미래·stale·실패·누락 참조가 포함된 현재 문장은 채택을 보류한다.

발행일 미확인·관측일 명시된 발행사 페이지는 그 관측의 공개판을 확보한 이후만 사용하고, 발행일을 관측·획득일로 채우지 않는다. 기존 날짜 단위 출처 검증과 별도로 정확한 시각의 공개·관측·획득 조건을 검사한다. 원문 구절의 좁은 확인, 공급자 전망의 발표 사실, 미래 실현과 가격 적정성은 구분한다. 실제 문장 검토에서 발견한 기간·비교 참조·지원되지 않는 주장도 새 연구 초안으로 수정하고 이전 판본을 보존한다.

### 자산별 자료의 검증

- **식별**: 대상 상품, 시장, 거래 통화, 가격 종류, 출처를 확정한다. 티커를 추측해 합치지 않는다.
- **형식**: 날짜·시간대·숫자·단위·스키마 버전을 검증한다. 무한값, 수치가 아닌 값, 잘못된 범위는 진단한다.
- **순서와 중복**: 명시된 키 기준으로 중복·역순·충돌을 검출한다. 정렬 보정 등 허용된 변환은 기록하며, 충돌 값 중 하나를 조용히 선택하지 않는다.
- **달력**: 시장 휴장과 실제 누락을 구분한다. 암호자산과 주식의 거래일을 같은 간격으로 간주하지 않는다.
- **시점**: 관측·공개·이용 가능·획득 시점과 개정 버전을 구분한다. 현재 자료라는 이유로 과거에도 이용 가능했다고 가정하지 않는다.
- **가격과 수익**: 가격 수익, 배당 포함 총수익, 분할 조정, 환헤지, 선물 교체 의미를 확인한다. `adjusted`라는 필드명만으로 총수익을 인정하지 않는다.
- **완전성과 적용 범위**: 상장폐지, 편입·편출, 재무 누락, 거래 중단이 분석 범위에 주는 영향을 기록한다.
- **이상치**: 진짜 시장 급변과 오류 가능성을 분리한다. 극단값을 자동 제거해 손실을 작게 만들지 않는다.
- **정렬**: 가격·환율·재무·거시 자료는 각 시점에 허용되는 정보만 연결한다. 미래의 가장 가까운 값으로 채우지 않는다.
- **교차 확인**: 중요 입력에 가능하면 다른 권위 있는 출처나 제공자와 비교한다. 불일치는 출처·조정 방식 차이를 진단하고 남긴다.
- **권리와 최신성**: 저장·재배포·사용 조건과 자료 나이를 확인한다. 최신성이 중요한 질문에는 허용 지연을 사전에 정의한다.

분석 유형별 필수 전제를 둔다. 가격 자료만 있는 과거 요약과 재무지표를 이용한 과거 신호 실험은 필요한 시점 보장이 다르다. 모든 자료에 하나의 통과 점수를 붙이지 않는다.

## 6. 정량 계산 계약

계산마다 정의, 입력 의미, 통화, 기간, 표본·달력, 비용·세금 처리, 방법 버전, 적용 불가 조건을 문서화한다.

현재 거시 변환은 Decimal precision 50·ROUND_HALF_EVEN의 고정 문맥을 쓰며 공식·출력 series·입력 observation ID·관측창·단위·가정·상태를 보존한다. YoY는 같은 월별 raw index의 정확한 현재·12개월 전 양수 endpoint로 `(current / prior - 1) * 100`을 계산한다. 중간 월 결측은 공개하되 필요한 두 endpoint가 있으면 계산 가능하다. 10년−2년 차이는 같은 날의 일별 명목 국채 수익률과 동일 단위·통화 맥락·조정 조건을 요구하며 결과는 percentage points다. 마지막 공통 날짜로 조용히 후퇴하지 않는다.

방향 표현은 명시한 차이의 부호다. 월별 비교는 정확한 비교 월, 일별 직전 비교는 실제 선택한 관측일을 표시하며 보간·forward-fill을 하지 않는다. CPI index 수준의 상승과 YoY 물가 상승률의 상승은 별개의 사실이다. 물가 상승률 방향은 현재 YoY와 정확한 전월 YoY의 차이로 계산하고 각 YoY endpoint가 없으면 차단한다. 한 비교창의 상승·하락으로 지속 추세·경제적 원인·자산 성과·침체 확률을 생성하지 않는다.

### 최소 원칙

- 가격 상승률과 배당 재투자 총수익률을 다른 결과로 취급한다. 배당이 이미 포함된 조정 자료에 배당을 더하지 않는다.
- 시간가중 수익과 자금 입출금을 반영한 수익을 구분한다. 입출금 경로를 지원하지 않는 초기 계산에는 입출금을 조용히 포함하지 않는다.
- 단순 수익률과 로그 수익률, 산술평균과 기하평균을 명시한다. 평균 기간 수익률을 복리 연간 수익률처럼 표시하지 않는다.
- 연율화는 달력·관측 간격·정의가 충족될 때만 한다. 자산별 거래일과 실제 경과 기간을 문서화하고 짧은 기간의 연율화 한계를 표시한다.
- 변동성의 단순 연율화는 수익률 의존성에 대한 가정을 갖는다. 불규칙 시계열이나 자기상관이 있으면 적용을 제한하거나 방법을 바꾼다.
- 최대 낙폭은 실제 관측된 동일 통화의 가치 경로에서 계산한다. 관측 빈도가 낮으면 기간 중 더 깊은 손실을 놓칠 수 있다.
- 금액과 세금의 반올림 규칙을 명시한다. 계산 중 표시 자릿수로 반올림하지 않는다. 수치 허용 오차와 표시 정밀도를 구분한다.
- 일관된 입력·버전·설정은 같은 결과를 내야 한다. 확률적 방법은 난수 시드와 방법·의존성 버전을 추가로 보존한다.

### 기본 정의의 예

양수인 총수익 가치 지수 `W_t`에서 외부 자금 입출금이 없으면 기간 수익은 `W_end / W_start - 1`이다. 최대 낙폭을 양의 손실 크기로 보고할 경우 `max_t(1 - W_t / max_{s≤t} W_s)`로 정의한다. 손실을 음수로 표시하는 방식과 혼용하지 않는다.

관측 가격만으로 만든 `W_t`는 배당 포함 지수가 아니다. 해당 정의는 분석 기간 동안의 관측 경로를 요약할 뿐, 미래 최대 손실이나 영구 손실 확률을 계산하지 않는다. 순자산이 음수가 될 수 있는 레버리지 경로는 이 단순 양수 지수 계약의 범위 밖이다.

## 7. 숫자 환각과 의미 왜곡을 제한하는 경로

1. 코드가 검증된 관측·계산을 ID로 등록한다. 값, 단위, 기준 시점, 기간, 범위, 불확실성, 출처를 연결한다.
2. 보고서의 수치 요소는 ID를 참조하는 구조로 만든다. 실제 값과 표본수는 렌더러가 삽입하며, LLM이 새로 계산한 값을 받아들이지 않는다.
3. LLM을 도입하면 허용된 근거와 질문만 제공한다. 주장은 유형, 지지·반대 근거, 가정, 범위, 논리 연결과 검증 상태를 포함한 제한된 구조로 받는다. 존재하지 않는 참조나 허용되지 않은 계산은 거부한다. 미검증 커뮤니티 주장을 사실로 바꾸거나 허용되지 않은 자산 순위·배분을 생성하지 못하게 한다.
4. 숫자뿐 아니라 기간, 단위, 비교 대상, 과거·미래 표현을 검사한다. “더 높다”와 같은 비교는 대응하는 계산 또는 관계 검증이 있어야 한다.
5. 검증에 실패한 생성 설명은 게시하지 않는다. 유효한 관측·계산과 검토된 주장은 정형 한국어 템플릿으로 설명한다. 검증되지 않은 의미를 템플릿 문장으로 확정하지 않는다.
6. 투자 논리에 대한 의미 검토를 남긴다. 자료가 보여 주는 상관을 원인으로 단정하거나, 제한된 근거를 전체 시장에 일반화하지 않도록 검토한다.

자유 문장 검사나 또 다른 LLM 판정만으로 환각을 완전히 제거할 수는 없다. 숫자를 글자로 쓰거나 인용을 잘못 연결하는 오류도 가능하다. 최초 보고서는 정형 문장으로 제한하고, 생성 설명을 추가할 때 허용된 주장 구조·참조·렌더링 검증과 사람이 읽는 검토를 함께 평가한다. 구조·참조 검증 통과는 문맥의 충실성, 논리의 타당성, 인과성, 개인 적합성을 자동 보증하지 않는다. 정성 추론은 검토된 해석과 한계로 남기며 자동으로 확정된 사실처럼 게시하지 않는다. 생성 실패를 숨긴 채 재시도를 반복해 그럴듯한 결과를 채택하지 않는다.

LLM은 조사 질문·서사·반대 논리·설명 초안을 제안할 수 있으나 스스로 근거 상태, 결론 강도, 현재 매력도, 투자 비중을 확정하지 않는다. 연구 범위와 주장 채택은 명시된 방법·전제 및 검토 기록을 따라야 한다. 근거가 강한 결론이 적거나 하나도 없는 실행도 정상적인 리서치 결과다.

외부 사실도 출처가 없는 숫자보다 낫다는 이유만으로 신뢰하지 않는다. 원문에서 확인되는 내용인지, 기준 시점과 수정 여부가 맞는지 확인한다. 인터넷 문장이나 LLM 기억은 원자료를 대신하지 않는다.

## 8. 불확실성을 나누어 설명한다

| 축 | 확인할 내용 | 보고서 표현 |
| --- | --- | --- |
| 자료 품질 | 출처, 결측, 개정, 시점, 표본 대표성 | 확인된 범위와 미확인 항목 |
| 방법 타당성 | 정의, 적용 조건, 독립 검산, 비용 처리 | 계산이 답할 수 있는 질문 |
| 통계 불확실성 | 표본수, 의존성, 분산, 추정 구간 | 추정의 불안정성과 방법의 가정 |
| 미래 적용 가능성 | 체제 변화, 경제적 이유, 표본 외 검증 | 가설과 실패할 조건 |
| 비교·사용자 적용 | 대안별 수익 정의·유동성·위험 차이, 개인 입력의 최신성·누락 | 부분 비교와 조건부 적합성, 판단 유보 범위 |

이 축을 섞어 임의의 “신뢰도 확률”을 만들지 않는다. 자료가 깨끗하고 계산이 맞아도 투자 기회가 존재한다는 뜻은 아니다. 결론 강도는 사전에 정한 분석별 기준과 근거 상태로 결정하며, 전 자산에 보편적인 최소 표본수를 임의로 적용하지 않는다.

## 9. 백테스트 설계

Minimum Viable Research System은 현재의 투자 대안과 사용자 제약에 대한 근거 검토다. 그 안의 과거 수익 요약은 전략 백테스트가 아니다. 백테스트는 특정 주장을 평가할 필요가 있을 때 선택하는 방법이며 시스템의 중심이나 모든 연구의 필수 단계가 아니다. 가설 실험은 아래 기준을 충족하는 이후 단계에서 구현한다.

### 실험 전에 고정할 내용

- 질문·경제적 가설, 투자 가능 집합, 신호·매매 시점, 관측 단위.
- 수익 기간, 비교 기준, 비용·세금 범위, 예상 손실 경로.
- 자료 버전과 정보 이용 가능 시점, 학습·검증·최종 평가 기간.
- 탐색할 조건·파라미터와 실험군, 선택 기준, 실패·중단 기준.
- 중복 관측과 표본 의존성을 처리할 방법, 불확실성 추정 방법.

사전 등록은 수익을 본 뒤 유리한 정의를 고르는 일을 제한한다. 이미 탐색한 가설은 탐색 연구로 표시하며 사전 등록한 것처럼 소급하지 않는다. 모든 시행·실패·파라미터 변형을 연구 기록에 남긴다.

### 주요 편향의 통제

| 문제 | 설계 대응 |
| --- | --- |
| 생존자 편향 | 당시의 구성과 상장폐지·퇴출 대상을 반영한다. 불가능하면 현재 생존 대상의 기술적 분석으로 범위를 제한한다. |
| 미래 정보 누수 | 공개·실제 이용 가능 시점의 자료를 사용하고 신호 이후 가능한 가격에 거래한다. 종가로 만든 신호를 같은 종가에 체결한 것으로 가정하지 않는다. |
| 자료 개정 | 거시·재무 자료의 당시 버전을 보존한다. 현재 수정 자료가 허용되는 실험인지 명시한다. |
| 선택 편향·데이터 탐색 | 탐색한 자산·조건·기간·파라미터 전체를 기록한다. 선택된 최고 성과만 게시하지 않는다. |
| 과적합 | 단순한 조건과 경제적 설명을 우선하고, 매개변수를 학습 구간에서만 추정한다. 시간 순서의 검증·walk-forward를 사용한다. |
| 겹치는 목표 기간 | 학습·평가 경계에서 목표 수익 구간이 겹치지 않도록 제외 구간을 둔다. 임의 순서의 교차 검증을 기본으로 사용하지 않는다. |
| 반복된 최종 평가 | 같은 최종 구간을 보고 수정하면 이후에는 미사용 평가 구간이라고 부르지 않는다. 새 기간의 순차 평가를 확보한다. |
| 비용·체결·유동성 | 수수료, 호가 차이, 슬리피지, 차입·펀딩, 선물 교체 등을 자료와 가정으로 모델링한다. 체결 불가와 거래 중단도 처리한다. |
| 체제 의존 | 시기·시장 상태별 결과와 실패 기간을 같이 보여 준다. 체제 정의에 미래 정보가 들어가지 않도록 한다. |

### 보고할 결과

수익 분포와 손실 크기, 관측 빈도, 보유 기간, 최대 낙폭과 관측된 회복 시간, 표본수·유효 표본수, 비용 민감도, 비교 기준, 표본 내·외 구분을 제시한다. 아직 회복하지 못한 경로는 회복 기간을 0으로 표시하지 않고 미회복 상태로 기록한다. 승률 하나로 유리함을 판단하지 않는다.

과거 양의 수익 관측 비율은 “정의된 과거 표본에서 양의 수익이 관측된 비율”로 표현한다. 독립성이나 정상성 가정이 없으면 단순 이항 표본의 구간을 붙이지 않는다. 시계열 의존에 맞는 구간 추정, 블록 재표집 등은 자료와 실험에 맞춰 선택하고 방법·한계를 공개한다. 이 구간을 미래 상승 확률의 보장으로 해석하지 않는다.

무작위 기준, 단순 보유, 적용 가능한 현금성 비교 기준과의 차이를 확인한다. 비교 자료가 없으면 그 비교를 계산하지 않는다. 다중 실험 보정과 민감도 분석은 유리한 결과를 증명하는 장치가 아니라, 선택 과정의 불확실성을 드러내는 장치다.

## 10. 반증 검토와 레버리지

가설마다 다음을 별도 작성한다.

- 가장 중요한 지지 근거와 그 근거가 증명하지 못하는 것.
- 반대 근거와 다른 설명, 아직 찾아보지 못한 반대 자료.
- 논리를 약화시키는 관측과 무효화 조건, 확인 자료와 재검토 시점.
- 기초자산이 맞아도 상품·환율·계좌·유동성 때문에 실패하는 경로.

반대 근거를 찾지 못하면 “없다”보다 “검토한 범위에서 확인하지 못했다”로 표시한다. 최초에는 같은 실행 내의 별도 검토 단계로 충분하다. 별도 LLM을 도입해도 모델 응답의 독립성과 자료의 독립성은 따로 평가한다.

레버리지는 기초자산 분석이 타당한 뒤에도 별도 심사 대상이다. 재설정, 경로 의존, 변동성에 따른 복리 손실, 비용, 증거금·청산, 회복에 필요한 수익을 검증해야 한다. 현물 기대수익·사용자 나이에서 자동 활성화하지 않는다. 관련 계약과 자료가 지원되지 않으면 해당 분석은 `blocked` 또는 `not_applicable`이다.

## 11. 필수 검증 범주

구현 시 다음 실패를 실제로 잡는 테스트를 단계에 맞게 추가한다.

- 수동 검산 가능한 합성 수익·낙폭 경로, 일정한 가치 경로, 양의 배율에 대한 수익률 불변성.
- 가격/총수익 혼동, 배당 중복, 분할, 비정상 값, 중복·누락·달력 오류.
- 환율 방향, 단위, 환율 미변동·자산 미변동 특수 사례, 환헤지 적용 범위.
- 공개 전 자료 사용, 시점 경계, 개정 자료와 당시 자료 차이.
- 거시 공개·vintage·revision·known-at·유효 시점의 미래 판본 차단, 공개/개정 이력 unknown의 획득 하한, UTC 일말과 정확 timestamp cutoff 차이.
- 최신 결측을 이전 값으로 대체하지 않음, source·단위·빈도·정의 변화, 정확 YoY endpoint와 중간 결측의 구별, index 방향과 상승률 방향의 구별, 동일 날짜·정의의 yield spread.
- 거시 live의 명시적 source 획득과 네트워크 없는 replay, 이전 pins 판본 보존, 관측·계산·근거·보고서 참조의 동일성, 전역 Decimal 문맥·입력 순서에 독립적인 결과.
- 존재하지 않는 근거 ID, 단위·기간이 다른 수치 참조, 누락을 0으로 출력하는 경우.
- 동일 실행 재현, 자료 변경 시 다른 체크섬, 오류가 결과와 종료 상태에 반영되는지.
- 획득 정책·timeout·파싱·누락 구절·원문 변경·보존 payload/메타데이터 해시 불일치, 고정 pins replay에서 네트워크 호출 없음.
- 발행일 미확인을 획득일로 채우지 않음, 미래 날짜의 우선 처리, stale 과거 사실과 현재 채택의 분리, 검토 날짜 역전.
- 지지·반대·배경·서사·숫자 assertion 참조의 자산 범위, 다른 정의·조정 방식의 숫자 비교를 확인/반박으로 확정하지 않음.
- 생성 설명의 거짓 수치·거짓 비교·미래 단정·근거 없는 인과·외부 지시문에 대한 거부.
- 존재하지만 해당 문장을 뒷받침하지 않는 인용, 범위를 벗어난 정성 주장, 상충 근거 누락과 동일 원출처의 중복 확인.
- 커뮤니티 발언을 사실로 승격, 확인 실패를 거짓으로 처리, 반복·조회수로 신뢰도나 미래 확률 생성.
- 다른 수익 정의·유동성·시점의 대안을 강제로 순위화, 비교 불가 상태 누락, 사용자 `unknown`을 기본값으로 채운 적합성·투자 비중 생성.

자산별 방법을 구현할 때 관련 검증을 추가한다. 검증하지 않은 금융 정의나 미래 적용 가능성을 테스트 통과만으로 보증하지 않는다.

## 실제 Deep Dive의 이익·가격 검증

[미국 주식 Deep Dive](us-equity-deep-dive.md)는 좋은 기업, 좋은 실적, 높은 성장과 좋은 투자 가격을 구분한다. 회사별 provider의 GAAP/non-GAAP convention·평가이익·세금 항목, 분기 EPS revision과 실현 이익·blended 추정, 서로 다른 forward 분모를 보존한다. 자료 없이 일회성 이익을 단순 차감해 지수의 “정상 EPS”나 예상 margin을 만들어내지 않는다.

원문 token과 좁은 숫자 정의를 대조한 `quoted_scalar_v1`은 전사 확인이다. 표의 열·기간·기업 선택과 해당 사실의 함의는 사람이 검토 완료한 자동 진실로 승격하지 않는다. run rate의 초과/근사 표현과 현금 지출의 괄호·음수를 보존한다. fact의 경제적 해석은 pending, 조건부 시나리오·경제적 주장은 unverified/draft다. source/HTML locator·excerpt-only·원출처 의존 한계는 유지한다.

AI 공급자 매출·마진은 구매자 ROI와 주주의 미래 수익을 증명하지 않는다. 전체 cloud 매출·CAPEX·depreciation을 AI 전용으로 바꾸지 않고, 증분 이익·전체 투자자본·현금 회수 자료가 없으면 그 범위의 판단을 유보한다. 같은 날짜의 EY−nominal Treasury yield도 설명용 차이이며 정의한 ERP나 기대 총수익률이 아니다. 숫자·출처 링크·테스트 통과가 이러한 경제적 함의를 자동 검증하지 않는다.
