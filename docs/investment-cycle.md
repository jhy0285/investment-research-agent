# 검증하고 결과로 수정하는 투자 시스템

2026-10-07부터 기존 조사에 **투자 가설 → 과거/최근 검증 → 현재 조건 → 행동 → 신규 현금 배분 → 불변 일지 → 사후검증 → 다음 판단 반영**을 연결했다. 자료 조사와 투자 승인은 다른 단계다. 새 Broad Scan은 첫 화면에 실제 행동과 1,000만원 예시 배분을 보여 준다. 이전 저장 보고서는 기존 방법·문장으로 재현한다.

강한 결론을 만들기 위한 숫자는 넣지 않는다. 반복 검증을 통과하면 A등급 분할 매수가 나오고, 사건 투자는 검토된 유사 사례와 현재 원자료가 있을 때 C등급 소액 매수까지 허용한다. 검증되지 않은 정량 전략은 신규 매수하지 않는다. 이 프로그램은 주문을 보내지 않는다.

## 실행

새 조사와 투자 결론을 함께 생성한다. 기존 공개 URL·공식 원자료 수집 경계를 사용한다.

```bash
python -m investment_research ask '현재 신규 자금을 투자한다면 어디에 투자하는 것이 가장 합리적인가?' --journal reports/investment_journal
```

장기 자료와 가설을 준비했으면 `--decision-plan my_investment_plan.json`을 추가한다. 계획은 네트워크 요청 전에 구조를 검증한다. `ask --replay <완료 실행>`은 인터넷 없이 판단·보고서를 재현한다. 다른 연구 모드에서 매수 판단까지 요청할 때도 같은 옵션을 사용한다.

이미 완료한 조사에 투자 가설을 연결할 수도 있다. 새로운 연구를 한 것처럼 날짜를 바꾸지 않고 그 조사의 원래 기준 시점을 사용한다.

```bash
python -m investment_research invest run my_investment_plan.json --research-run reports/my_scan --run-dir reports/my_decision --journal reports/investment_journal
python -m investment_research invest replay reports/my_decision
python -m investment_research invest record --run reports/my_scan --journal reports/investment_journal
```

이전 판단과 비교하려면 `invest run`에 `--previous-run reports/previous_decision`을 추가한다. 새 `ask --previous-scan`도 연결된 이전 투자 판단이 있으면 행동 변화와 이유를 기록한다. 이전 데이터는 현재 신호로 승격하지 않는다.

사후 가격을 확보한 뒤 평가한다. 가격 파일은 아래 데이터셋들의 JSON 배열이며, 투자상품과 비교 시장을 모두 포함한다.

```bash
python -m investment_research invest review --journal reports/investment_journal --prices outcome_prices.json --as-of '2026-12-10T18:00:00+09:00' --run-dir reports/my_outcome_review
```

평가 결과를 불변 일지에 보존한다. 이후 `ask --journal ...` 또는 `invest run --journal ...`은 판단 시점까지 존재한 최신 평가만 읽는다. `경고` 또는 `폐기 후보`인 동일 전략 버전은 신규 매수를 중단한다. 예약 실행·자동 데이터 갱신은 이 명령에 포함되지 않으므로 실제 새 자료와 평가 시점을 지정해 다시 실행한다.

## 입력 계약

`investment-plan-v1`은 `synthetic`, `new_cash_krw`, `scenario_note`, `policy`, `profile`, 최대 다섯 `candidates`를 갖는다. 빈 후보 계획의 실행 예는 [기본 계획](../examples/investment_cycle/no_validated_strategy.json)에 있다. 합성 실험의 모든 필드는 [재현 예제 생성기](../examples/investment_cycle/demo.py)로 생성할 수 있다.

`profile`에는 이번 신규 자금에서 남겨야 할 `reserve_krw`, 실제 감당 가능한 손실 금액 `loss_capacity_krw`, 감수 의향 `loss_tolerance_fraction`, 투자기간 `horizon_months`를 따로 적는다. 전체 보유·부채·계좌를 추정하지 않는다. 미입력 시 승인 전략도 **조건 충족 대기**, 현금 유지로 처리한다. 예시 배분을 개인 전체 자산의 적정 구성이라고 표현하지 않는다.

각 후보에는 다음이 필요하다.

| 항목 | 의미 |
| --- | --- |
| `asset_id`, `name`, `group`, `held` | 조사 대상, 이름, 서로 겹치는 노출, 보유 여부. 노출 그룹은 검토된 입력이며 ETF 개수로 분산을 주장하지 않는다. |
| `mode` | `quantitative`: 반복 정량 가설, `event`: 반복 표본이 없는 사건, `unvalidated`: 등록 검증 없음 |
| `reasons_up`, `reasons_down` | 지지/반대 논리를 각각 최대 다섯 개 |
| `review` | 의미 검토자, 시각, 범위·한계를 포함한 검토 메모. 코드가 인과적 의미를 대신 판정하지 않는다. |
| `evidence_ids`, `counter_evidence_ids` | 같은 조사 실행의 최신·검증·해당 자산 원자료. 커뮤니티·미래·격리·오래된 원자료는 채택하지 않는다. |
| `strategy`, `features`, `prices`, `benchmark` | 숫자로 정의한 가설과 당시 판본의 입력. 현재 상태는 검증 원문과 숫자·단위·정의·통화·관측일을 대조한다. |
| `current_price_evidence_id`, `max_price_age_days` | 실제 투자상품의 현재 기준가격과 허용 관측 나이 |
| `analog_evidence_ids` | 사건 투자일 때 검토한 비교 사례. 과거 수익률을 만들지 않고 C등급까지 제한한다. |

전략에는 ID·버전·가설·동결 시각 `locked_at`·시도한 변형 수 `trial_count`·보유기간·양방향 거래비용·과거/검증/최근 구간·진입 조건·가격 조건·무효화 조건을 등록한다. 각 조건은 `feature`, `op`, 숫자 `value`, `max_age_days`로 정의한다. 조건을 결과에 맞춰 자동 탐색하지 않는다. 독립기간 시작이 동결보다 이르면 거부한다. 입력된 과거 등록 시각의 외부 증빙은 별도 검토 대상이며 프로그램이 자기보고의 진실성을 증명하지 않는다.

과거 특징값은 `name`, `value`, `unit`, `currency`, `measure`, `source`, `observed_at`, `known_at`, `retrieved_at`, `vintage`를 갖는다. 현재 판본에는 검증 원문 `evidence_id`도 연결한다. 발표·개정 후에만 사용하며 같은 관측의 여러 판본을 덮어쓰지 않는다. 한 특징값의 정의·단위·정보원 변경은 같은 이력으로 조용히 이어 붙이지 않는다.

`investment-prices-v1`에는 상품/노출 ID·통화·단위·정의·출처·달력·획득 시점·가격/총수익 구분·조정 방식·생존편향 정책·합성 여부와 `at`, `known_at`, `value` 행을 넣는다. 중복·역순·결측·0 이하·비유한 가격을 거부한다. 총수익 지수에는 배당을 다시 더하지 않는다. `latest_adjusted` 또는 현재 생존 종목만 쓴 이력은 과거 설명용 계산까지만 허용하며 매수 승인을 하지 않는다.

신규 자금 배분에는 환율 노출을 포함해 검토된 **KRW 총수익**과 별도 시장 비교상품이 필요하다. USD 수익을 KRW로 이름만 바꾸거나 국채 금리를 채권 수익률로 대체하지 않는다. 외부 데이터 제공자의 장기 이력을 자동 수집하는 어댑터는 아직 연결하지 않았다. 가져온 자료의 권리·배당·환율·당시 판본을 검토해 이 계약으로 입력해야 한다.

## 계산과 승인

신호 확인 뒤 **다음 관측 시점**에 진입한다. 신호를 만든 종가로 바로 산 것처럼 계산하지 않는다. 1·3·6개월과 1년의 달력 보유기간을 계산하며, 각 독립 구간 안에서 만료된 결과만 평가한다. 휴일/자료 공백은 다음 7일 이내 관측으로만 처리한다. 월별 자료의 중간 하락은 월별 관측 범위의 값이며 일중·일별 최대 손실을 증명하지 않는다.

승인에는 겹치지 않는 신호 표본을 사용한다. 평균·중앙값·승률·평균 이익/손실·최대 결과·고점 대비 중간 하락을 계산한다. 같은 상품의 아무 날 매수, 같은 계절 매수, 같은 시점 시장, 구간 단순 보유와 함께 보여 준다. 조건 없는 두 비교는 기간이 겹치는 설명용 표본이다. 승률을 미래 확률로 표시하지 않는다.

수익 계산은 `매도값 × (1 − 매도비용) ÷ [매수값 × (1 + 매수비용)] − 1`이다. 비교 시장에도 등록한 동일 비용 가정을 사용한다. 세금·미체결·실제 슬리피지는 입력 비용에 포함된 범위를 넘어서 추정하지 않는다. 비용이 다른 대안은 정책 가정을 검토하고 별도 비교해야 한다.

현재 기본 승인 정책은 과거 20개, 독립 검증 10개, 최근 10개의 성숙·비중복 표본을 요구한다. 수익이 양수이고 조건 없는 매수·같은 계절·동일 시점 시장보다 좋아야 한다. 과거/검증의 시장 대비 평균 우위가 95% 재추출 구간에서 양수여야 강한 판단에 사용한다. 최근 구간의 불확실성이 남으면 B등급, 10년 이력보다 짧으면 B등급까지 허용한다. 여러 조건을 탐색한 전략·표본 부족은 매수 승인에 사용하지 않는다. 이 숫자들은 공개된 위험 관리 정책이며 과거 최고 성과를 찾은 결과가 아니다.

| 상태 | 행동 |
| --- | --- |
| 검증 통과 + 현재 조건/가격 충족 + 자금 제약 확인 | A 분할 매수, 제한이 남으면 B 소액 매수 |
| 검증 실패 또는 최근 붕괴 | 신규 매수하지 않음; 보유 중이면 비중 축소 검토 |
| 검증 좋음 + 현재 조건 없음 | 조건 충족 대기; 기존 보유의 자동 매도 사유로 사용하지 않음 |
| 현재 근거 미확인·격리·상품 가격 없음 | 강한 매수 차단 |
| 검토된 사건 투자 + 실제 현재 조건/가격 충족 | C 소액 매수까지 |
| 원자료로 확인된 가설 무효화 | 신규 매수하지 않음; 보유 중이면 매도 검토 |

배분 상한은 예시 정책으로 A 40%, B 20%, C 5%, 같은 노출 50%다. 남겨야 할 현금과 손실 한도를 지키며, 과거 하락폭을 미래 최대손실 보장으로 사용하지 않고 투자 원금 전체를 손실 감당 한도 안에 둔다. 승인 등급과 비교 가능한 최근 시장 대비 결과로 정렬한다. 검증 부족 후보의 번호는 조사 순서이며 수익 우위가 아니다. 서로 다른 기간의 전략을 같은 순위로 섞지 않는다.

분할 진입은 다음 월간 점검 때 조건·원자료·제약을 다시 확인하는 운영 방법이다. 임의의 -5%/-10% 진입가를 넣지 않는다. 달력 분할이 일괄 매수보다 수익률이 높다고 주장하지 않는다. `amount_krw`는 신규 자금의 배정액이고 실제 주문 체결액은 아니다.

## 기록과 학습

`investment_decision.json` 또는 `decision.json`에 판단일·가격·행동·등급·금액·이유·백테스트·현재 조건·보유기간·무효화 조건을 보존한다. 일지의 `decisions/<내용 해시>.json`, `strategies/<ID>/<버전>.json`, `reviews/<내용 해시>.json`은 변경하지 않는다. 같은 내용을 다시 기록하면 중복 저장하지 않는다.

사후검증은 판단 후 7일 이내의 다음 가격에 진입한 **추천 신호 평가**다. 실제 계좌 수익이 아니다. 1주·1/3/6개월·1년을 분리하고 해당 보유기간이 만료되어야 계산한다. 자료 부족/미성숙을 0%·승리·패배로 채우지 않는다. 같은 자산의 겹치는 추천과 다른 전략 버전으로 재추천한 거래도 독립 표본에 중복 집계하지 않는다. 합성 결과와 실제 결과도 분리한다.

등급별 성과와 같은 버전의 성숙 표본을 평가한다. A가 C보다 나쁘면 등급 규칙 재검토를 표시한다. 과거 승인 전략은 `승인`, 실전 표본 부족은 `검증중`, 충분한 실제 시장 대비 우위는 `강한 승인`, 최근 악화는 `경고`, 지속적인 우위 소멸은 `폐기 후보`로 관리한다. 우연·금리·시장 구조·비용·상품·진입 지연·개정·표본·정책/경쟁의 점검 항목을 남긴다. 가격만으로 원인을 확정하거나 자동으로 새로운 조건을 만들지 않는다.

전략 수정에는 **새 버전**, 이전 정의의 `parent_sha256`, 변경 이유, 더 늦은 동결 시점, 새 독립 검증기간이 필요하다. 과거 정의와 결과는 보존한다. 새 버전이 같은 과거 구간에 잘 맞았다는 이유로 실전 승인하지 않는다.

## 현재 구현 범위

요청의 시장 스캔·가설·시점 검증·최종 행동·등급·1,000만원 배분·진입·무효화·일지·사후 성과·등급 비교·전략 상태·새 버전·이전 판단 비교는 실행 가능한 코드로 연결했다. 강한 매수와 매수 차단의 양쪽을 합성 fixture로 검증했다.

전체 시장의 실제 장기 이력, 과거 이익 전망의 최초 발표 판본, 모든 시장의 같은 정의 가격, 개인 계좌 체결, 원화 환산/세후 어댑터, 자동 갱신/예약 실행은 아직 미지원이다. 은·산업금속·기타 주요 암호화폐·글로벌 부동산은 점검 목록과 미지원 표시만 있으며 별도 수집 계약은 없다. 기존 15영역 수집을 전체 시장의 완전한 조사라고 표현하지 않는다. 등록한 검증 자료가 없는 실제 실행은 **신규 매수하지 않음 / 예시 현금 1,000만원 유지**로 끝내며 검증 성공을 만들지 않는다.
