# 시점 보장 장기 이력 수집

2026-10-22 추가했다. [투자 판단과 사후검증](investment-cycle.md)은 과거·독립·최근 검증에 **당시 알 수 있었던 값**을 요구하지만, 그동안 실제 장기 이력을 가져오는 어댑터가 없어 사용자가 직접 계약 형식으로 입력해야 했다. `invest history`는 검토된 공개 제공자 몇 곳에서 이 입력을 자동으로 만든다.

이 기능은 **자료를 모으는 단계**다. 투자 등급·순위·매수 승인을 만들지 않는다. 가격 이력을 총수익으로 바꾸지 않으며, 가져온 이력이 오늘의 숫자를 검증된 사실로 만들지도 않는다.

## 실행

```bash
python -m investment_research invest history acquire examples/investment_history/btc_macro_spec.json --output reports/history_btc_macro
python -m investment_research invest history replay reports/history_btc_macro
```

`acquire`는 인터넷에서 받아 새 디렉터리에 저장한다. `replay`는 보존한 행만으로 결과를 다시 만들고 모든 파일의 해시와 내용을 대조한다. 인터넷을 쓰지 않는다. 실패한 항목이 있으면 종료 코드 1, 명세·경로 오류는 2, 정상 완료는 0이다.

| 파일 | 내용 |
| --- | --- |
| `spec.json` | 실행한 수집 명세 |
| `snapshots.json` | 요청 URL·획득 시각·원문 SHA-256·바이트 수와 판단에 쓰는 관측창 행. 접근 정책 확인 기록 |
| `history.json` | `investment-prices-v1` 가격 데이터셋과 특징값 행, 요약, 실패, 한계 |
| `history.md` | 쉬운 한국어 요약 |
| `history_manifest.json` | 위 네 파일의 해시 |

실제 자료는 `reports/`처럼 저장소에 커밋하지 않는 위치에 둔다. 개인 연구 재현용이며 재배포하지 않는다.

## 검토된 제공자

목록에 없는 제공자·시장·계열은 네트워크 요청 전에 거부한다. 계약은 [catalog/history.json](../investment_research/catalog/history.json)에 있다.

| 제공자 | 대상 | 시점 규칙 | 주의 |
| --- | --- | --- | --- |
| Upbit 공개 시세 API 일 캔들 | `KRW-BTC`, `KRW-ETH` (2017-09-25 이후) | 관측 시각은 캔들 종료(00:00 UTC = 09:00 KST). `known_at`은 종료 시각과 마지막 틱 저장 시각 중 늦은 쪽. 아직 끝나지 않은 오늘 캔들은 버린다 | **가격 수익**이다. 하드포크·에어드롭·스테이킹 보상을 포함하지 않으므로 총수익 판본이 아니다 |
| St. Louis Fed ALFRED 판본 CSV | `CPIAUCSL`, `UNRATE`, `FEDFUNDS`, `DGS10`, `DEXKOUS` | 요청한 판본일 당일 미국 중부시각 자정(다음 날 06:00 UTC) 이후, 단 실제 획득 시각보다 늦지 않게 | 미국 정부 공표 자료만 등록했다. robots.txt의 Crawl-delay 2초를 지킨다 |

Upbit의 `timestamp` 필드는 체결 시각이 아니라 캔들의 마지막 틱이 **저장된** 시각이다. 실제 응답에서 종료 직후 수 밀리초로 관측되어, 종료 후 60초까지만 허용하고 그보다 크면 자료 오류로 거부한다.

## 시점 누수를 막는 방법

- **판본 표본.** ALFRED에서 `vintage_start`부터 `vintage_step_days` 간격(7~92일)과 오늘의 판본을 받는다. 각 판본에서 새 관측이나 **고쳐진 값만** 새 행으로 남긴다. 그래서 같은 관측의 처음 발표값과 개정값이 서로 다른 `known_at`으로 함께 보존되고, 과거 시점의 조건 판단은 그때 보였던 값만 쓴다. 표본 사이에 나온 발표는 다음 표본일에 보인 것으로 기록되므로 실제보다 늦을 수는 있어도 이르지 않다.
- **관측창 인자 금지.** ALFRED에 `cosd`/`coed`(관측 시작·끝) 인자를 붙이면 판본이 아닌 값이 섞여 돌아오는 것을 실제 응답으로 확인했다. 예를 들어 2020-03-02 판본에 아직 발표되지 않은 2020년 3월 CPI가 들어 있었다. 그래서 항상 전체 판본을 받아 로컬에서 `window_days`만큼만 보존한다. 판본일보다 늦은 관측이 하나라도 있으면 그 응답 전체를 거부한다.
- **관측창 밖 개정.** 각 판본에서 `window_days` 안의 관측만 보존하므로, 관측창을 벗어난 오래된 관측의 개정(예: 매년 2월 CPI 계절조정 개정)은 기록하지 않는다. 조건 판단은 그 시점에 보인 **가장 최근 관측**만 쓰므로 판단에는 영향이 없지만, 오래된 관측의 값 자체를 분석할 용도로 쓰면 안 된다.
- **철회 감지.** 이전 판본에 있던 관측이 같은 관측창 안에서 이후 판본에서 사라지거나 결측으로 바뀌면 그 특징값 전체를 실패로 남긴다. 특징값 행은 "더 이상 없음"을 표현할 수 없고, 옛 값을 그대로 두면 철회된 숫자를 보여 주게 되기 때문이다.
- **헤더 확인.** CSV 첫 줄이 요청한 계열·판본일(`CPIAUCSL_20200302` 등)과 다르면 거부한다.
- **결측은 결측.** `.`·빈 값은 0으로 바꾸지 않고 건너뛴다. 가격의 빈 날짜도 채우지 않는다.
- **같은 판본 안의 전년 대비.** `transform: "yoy_percent"`는 월별 계열에서만 허용한다. 각 판본 안에서 정확히 12개월 전 같은 달의 값으로 계산한다. 개정된 이번 달 값과 다른 판본의 기준월을 섞으면 당시 누구도 볼 수 없던 숫자가 되기 때문이다. 기준월이 없으면 값을 만들지 않는다.
- **파생 가격 특징값.** `trailing_return`(N일 전 종가 대비 수익률)과 `close_to_sma`(최근 N개 종가 평균 대비 괴리)는 그 시점까지 알려진 행만 쓰고 `known_at`은 사용한 행 중 가장 늦은 시각이다. 기준 관측이 7일보다 멀거나, N개 종가가 24시간 시장 기준 (N−1)+7일보다 넓게 흩어져 있으면(평균 안에 빠진 날이 있으면) 값을 만들지 않는다.

## 수집 명세

```json
{
  "schema_version": "investment-history-spec-v1",
  "prices": [{"provider": "upbit_day_candles", "market": "KRW-BTC", "start": "2017-10-01"}],
  "features": [
    {"name": "us_cpi_yoy", "provider": "alfred_vintage_csv", "series": "CPIAUCSL", "transform": "yoy_percent",
     "vintage_start": "2019-01-01", "vintage_step_days": 30, "window_days": 500},
    {"name": "btc_return_90d", "provider": "price_derived", "instrument_id": "UPBIT_KRW_BTC",
     "kind": "trailing_return", "days": 90}
  ]
}
```

가격은 최대 다섯, 특징값은 최대 스무 개다. 예상 요청 수가 800을 넘으면 실행 전에 거부한다. 일시적인 시간 초과·연결 끊김·429/5xx 응답은 1초부터 두 배씩 늘린 간격으로 최대 두 번 다시 요청하며(robots.txt 확인도 요청 수와 Crawl-delay에 포함), 그래도 실패하면 그 항목만 실패로 기록하고 값을 만들지 않는다.

## 투자 계획에 연결하기

`history.json`의 값을 [투자 계획](investment-cycle.md#입력-계약) 후보에 넣는다.

```python
import json
h = json.load(open('reports/history_btc_macro/history.json', encoding='utf-8'))
candidate['prices'] = h['prices']['UPBIT_KRW_BTC']
candidate['features'] = h['features']['btc_return_90d'] + h['features']['us_cpi_yoy']
```

- **비교 시장**은 같은 통화·같은 수익 정의의 별도 상품이어야 한다. 어떤 상품이 그 전략의 시장 대안인지는 사용자가 검토해 정한다. 예를 들어 ETH를 BTC의 비교 대상으로 쓰는 것은 계약 형식만 맞을 뿐, 그것이 적절한 시장 대안이라는 판단은 아니다.
- **매수 승인은 막힌다.** 현재 기본 정책은 배당·분배를 포함한 시점 보장 총수익 이력을 요구한다. 이 가격 이력으로는 백테스트가 “배당·분배금을 포함한 실제 상품 수익률이 아니다”라는 차단 사유와 함께 설명용으로만 실행된다. 비배당 현물 코인의 가격을 총수익으로 볼지는 포크·에어드롭 처리까지 검토한 뒤 정할 일이며 코드가 대신 정하지 않는다.
- **오늘의 조건**은 여전히 조사 실행에서 검증한 원문 수치와 값·단위·정의·관측일이 맞아야 한다. 이력 행만 있으면 현재 판단은 보류된다.
- 사후 평가(`invest review --prices`)에 판단 이후의 실제 가격 이력으로 쓸 수 있다.

## 지원하지 않는 것

주식·ETF 총수익 지수, 한국 거래소 가격, 원화 환산 총수익, 과거 이익 전망 판본, 자동 예약 갱신은 아직 없다. FRED의 최신 CSV는 개정 이력이 없으므로 과거 판단용 이력으로 쓰지 않는다. 이 기능으로 받은 자료를 전체 시장의 완전한 이력이라고 표현하지 않는다.
