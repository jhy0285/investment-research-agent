# 보고서와 설명 설계

2026-10-07부터 새 Broad Scan에는 [투자 판단 보고서](investment-cycle.md)를 앞에 붙인다. 검증 등급·최종 행동·신규 1,000만원 예시 배분을 먼저 보여 주고 기존 설명형 조사·근거 부록을 유지한다. 아래 기존 연구 단계의 '추천 생성 안 함'은 이전 문장과 원자료 해석의 경계다. 새 행동은 별도 검증 정책의 결과이며, 미검증 전략을 그럴듯한 문장으로 승인하지 않는다. 과거 저장 보고서는 당시 방법 그대로 재현한다.

## 1. 기본 형태

보고서는 “현재 이 사용자가 자신의 자본을 어디에 배분할지 판단하기 위해 무엇을 알아야 하는가?”에 답한다. 현재 시장의 핵심, 조사할 투자 기회, 대안과의 기회비용, 사용자 제약, 반대 논리와 더 확인할 조건을 연결한다. 가격 지표 목록이나 BUY/HOLD/SELL을 최종 결과로 삼지 않는다.

기본 사용자 본문은 **쉽지만 충분히 자세한 한국어 설명형 보고서**다. 짧은 뉴스 요약으로 줄이기 위해 근거·반대 논리·위험·숫자의 의미를 삭제하지 않는다. 사용자가 왜 지금 이 자산을 보는지, 무엇이 좋아지고 있는지, 무엇이 잘못되면 손실이 나는지, 현재 가격이 기대를 이미 반영했는지, 무엇을 더 확인해야 하는지를 자기 말로 설명할 수 있어야 한다. 정보 기준 시점, 사용자 정보의 기준 시점, 조사 범위와 핵심 한계도 드러낸다. 강한 결론이 적거나 없다는 결과도 정상이다.

전문용어는 처음 쓰는 자리에서 쉬운 한국어 뜻과 투자 의미를 설명한다. 예를 들어 CAPEX는 공장·설비·데이터센터처럼 미래 생산능력을 늘리는 투자비용이며, 수요가 강하면 기회를 늘리지만 약하면 회수가 늦어지고 남는 현금이 줄 수 있다고 연결한다. 숫자에는 관측 기간·단위와 의미를 붙인다. 가능한 경우 **실제 변화 → 왜 중요한가 → 가격에 반영된 기대 → 투자자에게 의미 → 판단을 바꿀 조건** 순서로 설명한다. 금리를 제시하면 받을 이자 대안과 위험자산의 기회비용까지, 이익 증가를 제시하면 반복 가능성과 현재 가격까지 연결한다.

짧은 예시·비유는 개념을 이해하는 도구다. 선물 교체나 일별 배수 상품의 예시는 **현재 시장가격·약관·성과가 아닌 설명용 예시**로 표시한다. 교육용 예시를 실제 evidence나 새로운 계산 결과로 등록하지 않는다. 설명을 덧붙여도 원문 일치·수치 확인을 경제적 논리의 검증 완료나 매수 근거로 승격하지 않는다.

새 `ask`의 보고 형식은 `ask_report_explanatory_ko_v5`로 고정한다. 기존 설명형 v1·v2·v3과 이번 작업의 첫 v4 예시도 같은 바이트로 재현한다. 작은 비율의 표시 정밀도·한국어 단위·기본 본문/원문 분리와 EPS를·PER로처럼 한국어 조사가 붙은 용어의 첫 설명을 유지한다. v4의 자산별 설명 범위·마지막 시장 종합 문단에 이어 v5는 crypto 선물의 담보·청산 설명을 일별 배수 상품의 설명과 구분한다. `report_explanations.py`는 기존의 확인된 값·계산·후보·조건부 해석을 읽어 설명하는 출력 함수다. 획득·검증·정량 계산·후보 선정·routing은 그대로 사용한다. 세부 원자료·원문·계산식·claim·hash·replay는 펼쳐 보는 상세 근거와 기존 JSON artifact에 남고, 본문의 짧은 링크가 해당 근거로 이어진다. 과거 형식 표식이 없는 실행은 기존 `ask_report_v1`의 같은 바이트로 replay한다. 기존 파일의 문체나 근거를 소급 수정하지 않는다.

**자산별 설명 범위:** 해당 자산의 수익 구조와 실제 조사 대상에 맞는 용어·관측·계산만 본문에 넣는다. BTC의 ‘PER로 평가하지 않는다’ 같은 부정 문장에서 회사 이익 배수의 설명을 생성하지 않으며 본문은 사용·보유 수요와 실제 자금흐름으로 설명한다. ETF는 기초 노출도 확인한다. Compare에서는 명시한 대안의 지표를 유지하되 한 자산의 계산을 다른 자산의 설명에 붙이지 않는다. Scan과 Deep Dive를 함께 실행해도 별도 심층 본문에 전체 시장의 이익·지역 자료가 섞이지 않아야 한다. 환율·금리·물가의 관측과 그 변화 계산은 별도 **시장 환경**에서 설명하고 자산 자체의 가격·수익 계산과 구분한다. 원화 국채에 달러 환산 설명을 일괄 붙이지 않는다. 출력 범위의 제한은 원래 evidence나 계산을 삭제하는 것이 아니다.

시장 전체 질문의 기본 본문은 `오늘 시장을 이해하는 핵심`, `지금 가장 볼 만한 곳`, `지금은 덜 매력적인 곳`, `지난 Scan 이후 달라진 점`, `시장 전체 그림`, `다음에 깊게 볼 것`을 중심으로 구성한다. 각 실제 후보에 `왜 지금 보는가`, `쉽게 말하면`, `좋은 점`, `걱정할 점`, `시장이 이미 기대하고 있는 것`, `무엇을 확인하면 더 강한 기회가 되는가`, `지금 판단`을 붙인다. 후보 수·판단 강도는 기존 조사 결과를 따르며 칸을 채우려고 자산을 추가하지 않는다. 자료가 부족한 자산과 실제 긍정 근거가 약한 자산을 구분한다. Deep Dive·Compare·Portfolio Review에도 같은 설명 난이도를 적용하며 넓은 시장의 후보 구조를 강제하지 않는다.

**종합 설명:** 비후보는 상태·핵심 이유·위험만 짧은 표로 압축한다. 자산별 반대 논리·미확보 자료·다시 볼 조건은 상세 근거에 유지한다. 마지막에는 **그래서 지금 시장은 어떤 시장인가**를 1~3문단으로 설명한다. 실제 후보의 수익 기반·가격에 들어간 기대·확인한 국채 이자 대안·남은 불확실성을 연결하며 자산 목록을 다시 길게 반복하지 않는다. 새 점수·시장 국면 확정·유동성 개선·매수 명령을 만들지 않는다. 후보가 없다면 결론을 유보하는 이유를 연결해서 설명하고 현금의 우월성을 도출하지 않는다.

[독립 연구 모드](research-modes.md)에 따라 본문을 선택한다. Scan은 조사할 영역·변화·보류 이유, Deep Dive는 지정 대상의 기대/실제 근거와 반대 논리, Compare는 지정 대안의 고유 경제성과 축별 비교, Portfolio Review는 실제 보유·제약·기존 노출·추가 보유 효과를 중심으로 설명한다. 후보 목록과 Broad Scan 섹션을 모든 보고서의 필수 칸으로 두지 않는다. 순위·추천·개인 적절성을 확정할 근거가 부족하면 그 판단을 유보한다. 계획 JSON은 연구 보고서와 구분하고 미실행 상태를 표시한다.

현재 합성 오프라인 MVP와 실제 공개 source 검증 MVP는 같은 정형 Markdown 연구 보고서 경로를 사용한다. 계산 값·입력 상태와 검토 기록을 코드가 채우므로 외부 LLM은 필요하지 않다. 이후 생성 설명과 화면을 붙여도 같은 근거·실행 기록을 사용한다. [생성된 합성 예제](../examples/cross_asset_case/research_brief.md)는 실제 시장 분석이 아니며, [실제 source 사례](../examples/real_world_case/README.md)는 과거 사건의 출처·주장 검증을 보여 준다.

예제는 질문, 한눈에 보기, 투자환경, 대안별 분석, 커뮤니티, 상충 근거, 개인 정보 부족, Insight, 재검토 조건, 최대 5문장 설명의 10개 본문 섹션과 근거 부록으로 구성한다. 본문의 ID는 부록으로 연결한다. 검토 전 해석이나 부적격 근거를 참조한 기회비용·재검토 설명은 채택 보류로 표시한다. 상대 매력 순위와 미래 확률은 출력하지 않는다. 아래 상품·계좌·세금·실제 집중위험 항목은 자료·방법이 추가된 이후 범위다.

### 실제 Opportunity Map의 현재 범위

[생성된 지도](../examples/opportunity_map_case/opportunity_map.md)는 15개 영역의 현재 상태·긍정/반대 근거·불확실성·기회비용·연구 우선순위를 비교한다. 기관 전망과 실제 사업 실적·원관측, 공개 댓글의 발언 존재·미검증 내용, 시장 질문과 개인 위험 감당 능력을 구분한다. 최대 4개 후보를 허용하지만 강제로 선정하지 않으며 이번 사례는 3개다. 후보와 연결된 다음 Deep Dive 한 개는 제안만 출력한다.

전체 해석은 고정 입력의 연구 초안이다. 일반 prose에는 금융 숫자를 직접 넣지 않고 주요 수치는 원문 구절 또는 기존 macro 계산에서 나온다. 참조가 실패·stale·미래이면 해당 현재 문장은 채택 보류로 표시한다. 현재 커뮤니티 발언은 관측된 서사로 유지하고 사실·통계적 consensus로 승격하지 않는다. 구체적인 계약·재현과 한계는 [Opportunity Map 안내](opportunity-map.md)에 있다.

### 실제 거시 보고서의 현재 범위

[Macro Regime Snapshot](../examples/macro_case/macro_snapshot.md)은 고정 정보 기준 시각, 금리·물가·환율, 상충 여부와 조건부 전파 경로, 미확인 범위, 쉬운 설명을 한국어로 출력한다. 모든 주요 숫자는 원관측 EvidenceRecord 또는 검증된 MetricResult와 연결하며 계산식·입력·단위·기간·source snapshot을 공개한다. 원지수 변화와 YoY 상승률의 변화를 구분하고, 서로 다른 관측 기간을 같은 추세로 표현하지 않는다.

사실과 계산은 결정적 규칙으로 만든다. 자산에 영향을 줄 수 있다는 문장은 검토 전 조건부 해석 후보이며, 금리·환율 관측만으로 수익 예측·매력도·사용자 적절성을 확정하지 않는다. 과거 조회에서는 기준 시점 뒤에 확보한 판본과 발표 확인 자료를 사용하지 않는다. 자료가 차단되거나 오래되면 현재 수치를 숨기고 이유와 보류 상태를 보여 준다. 실행과 정의는 [거시 안내](macro-mvrs.md)를 따른다.

### 실제 source 검증의 현재 보고 범위

실제 사례는 **2024-09-18 정책 발표를 고정 기준일 2026-10-04에 사후 확인**한다. 4개 공개 출처·6개 근거·4개 주장을 현재 시장 분석이나 개인에게 유리한 자산 평가로 표현하지 않는다. 과거 발표의 확인 결과와 현재 기준의 오래된 자료 상태를 함께 표시한다. KRW 외의 개인 정보는 unknown이며 개인 추천·투자비중을 생성하지 않는다.

| 주장 | 결과를 표현하는 범위 |
| --- | --- |
| 당시 Fed가 발표한 인하 폭은 50bp | 같은 정책 결정·단위·정의의 좁은 수치 비교로 확인; 투자수익과 구분 |
| 같은 발표가 25bp라고 입력한 점검 주장 | 공식 구절과 수치가 불일치함을 표시; 실제 커뮤니티 발언이 아닌 검증용 점검임을 명시 |
| 댓글의 50bp 사실과 더 일찍 인하했어야 한다는 해석 | `partially_supported`; 공식 수치와 맞는 부분과 확인하지 못한 해석을 분리한 사례 검토 기록 |
| 모든 인하 시작이 침체 직전이었다는 댓글 | `unverified`; 발언 존재만 관측했으며 전체 주기·침체 정의·시점 자료가 부족함을 공개 |

지지·반대 근거와 별도로 `context_ids`를 표시한다. Fed의 당시 경제 확장 평가나 QuantEcon의 경기 개념 설명은 다른 관점을 제공하는 맥락이며 커뮤니티의 침체 우려를 반박한 근거로 자동 변환하지 않는다. 물가의 진전과 여전히 높은 수준도 함께 성립할 수 있다. `reviewed_links_v1`의 정성 상태는 명시된 사례 검토 기록이며 런타임의 자동 의미 판정이 아니다.

부록은 source ID·canonical URL·발행 주체·제목·snapshot ID·획득 시점·공개/관측/유효 시점과 unknown, 원문 구절·locator·definition, 보관 방식·해시·권리, freshness와 획득 실패 진단을 연결한다. 근거의 내용 확인·해석 검토·주장 상태를 구분한다. Text/HTML의 설명용 locator는 입력된 검토 정보이고 자동 검사는 정규화된 구절 일치이며, JSON pointer는 선택한 문자열 필드를 추적한다. excerpt만 보관한 source의 전체 원문을 재생에서 다시 해시했다고 표현하지 않는다.

출처 수집은 기존 acquire 경계에서만 수행하며 기본 `ask`도 선택한 source/macro 계획으로 이 함수를 재사용한다. 모든 replay는 고정된 pins와 snapshot을 읽어 같은 기준 시점·방법의 보고서를 인터넷 없이 재현한다. 실패한 출처는 정상 근거로 대신 채우지 않고 영향을 받은 주장과 진단을 남긴다. 실행 방법과 자세한 한계는 [source 획득 안내](source-acquisition.md)에 둔다.

### 자연어 ask의 현재 보고서

[Research Orchestrator](research-orchestrator.md)는 원래 질문·기준 시각·결론·원자료의 핵심 단서에서 시작한다. Scan·지정 대상·비교·보유에 필요한 본문만 선택하며 mode 이름을 사용자가 이해해야 읽을 수 있는 보고서로 만들지 않는다. 본문의 판단·수치·원문 링크와 부록의 source/snapshot·definition·입력/방법, manifest의 reasoning·claim·반대 설명·누락 질문을 연결한다. 영어 원문·내부 ID·해시는 부록에서 조사할 수 있다. 실패·미지원·unknown을 숨기지 않고 검토 전 해석은 pending으로 유지한다. Portfolio Review의 알려진 평가액 비중은 권고 비중과 구분한다.

## 2. 보고서 구성

| 순서 | 사용자에게 답할 질문 | 필수 내용 |
| --- | --- | --- |
| 연구 질문과 상태 | 지금 누구의 어떤 판단을 돕기 위해 조사했나? | `ResearchBrief`·`ProfileSnapshot` 버전, 정보 기준 시점, 기간·통화, 완료·부분·차단 상태 |
| 현재 시장에서 중요한 것 | 이번 질문에 실제로 중요한 변화와 위험은 무엇인가? | 관련 거시·신용·유동성·산업·가격 근거, 전달 경로, 자료 시점·범위 |
| 모드와 조사 범위 | 실제 질문에 왜 이 범위·방법을 사용했나? | 명시/해석한 모드·대상·방법·한계; 후보·우선순위·제외는 Scan에 해당할 때만 표시 |
| 대안 비교와 기회비용 | 위험을 감수하고 이 노출을 보유할 이유가 있는가? | `ComparisonFrame`, 현금·국채 등 관련 대안, 확인된 차이·조건부 차이·비교 불가, 비용·유동성·불확실성 |
| 기회 가설과 반대 논리 | 어떤 기회가 보이고 어떤 설명이 이를 약화시키나? | 지지·반대 근거, 가정·가격 반영 가능성·다른 설명, 아직 확인하지 못한 주장 |
| 사용자 적용과 집중 위험 | 시장 기회가 현재 사용자에게도 적절한가? | 필요 자금·부채·주택 계획·투자기간·기존 노출·손실 감당 능력, 확인된 조건·미확인 입력·조건부 해석 |
| 한국 투자수단과 손실 경로 | 같은 노출을 실제로 보유하면 무엇이 달라지나? | 원 통화/KRW, 상품 구조·환헤지·유동성·비용·세금·계좌 조건, 적용 상태·출처·유효기간 |
| 무효화·관찰·재조사 조건 | 무엇이 달라지면 기회가 좋아지거나 해석을 고쳐야 하나? | 관찰할 항목·자료·조건·시점, 가설을 약화시키는 조건, 필요한 추가 조사 |
| 판단 가능 범위와 유보 | 지금 무엇까지 판단할 수 있고 무엇은 기다려야 하나? | 근거가 충분한 제한된 결론, 미확인·상충·유보의 이유; 투자하지 않고 관찰할 조건 |
| 근거와 재현 부록 | 직접 검토·재현할 수 있나? | 주장→근거→출처/계산 연결, 출처 등급과 검증 상태, 원문 위치·버전·시점, 실행·방법 버전·가정 |

위 표는 활용할 보고 요소이며 공통 강제 workflow가 아니다. 짧은 보고서에도 질문·실제 조사 범위·관련 대안·사용자 적용 범위·반대 논리·결론 한계는 드러나야 한다. 필요한 자료가 없으면 이유와 영향받는 판단을 명시한다. 시장 자체의 분석에서 실제 포트폴리오 전체가 적절하다고 결론내리지 않는다. 투자 thesis가 확인되지 않았으면 문장을 만들어 칸을 채우지 않는다. 과거 계산은 필요한 근거로 연결하되 현재 매력도 결론을 대신하지 않는다.

### 비교 표의 기본 계약

대안별로 경제적 노출, 접근 가능한 상품, 검토 이유, 수익의 원천, 주요 손실 경로, 유동성·보유 제약, 비용·세금 확인 상태, 사용자에게 관련된 조건, 지지·반대 근거, 비교 가능 상태를 나란히 보여 준다. 정의가 맞는 수치만 추가한다. 현금 이자·국채 수익률·주식의 과거 평균·부동산 임대수익을 한 열에 넣어 숫자만으로 순위를 매기지 않는다.

기회비용은 같은 기간·통화·제약에서 다른 대안을 선택했을 때 포기하는 가능한 이익과 감수하지 않아도 되는 위험으로 설명한다. 수치화가 가능한 부분과 모형·가정에 의존하는 부분을 나누고, 비교가 불가능하면 그 사실을 결과로 남긴다. 현금 보유·대기의 선택 가치도 검토하지만 결론 유보만으로 현금이 우월하다고 말하지 않는다.

## 3. 주장 유형

| 표시 | 의미 | 필요한 연결 |
| --- | --- | --- |
| 관측 사실 · observed fact | 검증된 시계열 등에서 직접 확인한 사건·값 | 관측 ID, 출처, 시점·단위 |
| 외부 사실 · externally sourced fact | 상품 설명·공시 등 외부 문서의 확인된 주장 | 문서·구절·버전·유효 시점 |
| 계산 결과 · calculated result | 명시된 입력과 방법으로 산출 | 계산 ID, 입력, 정의·기간·방법 버전 |
| 해석 · interpretation | 근거를 연결하는 의미·설명 | 관련 근거, 연결 논리, 한계와 대안 |
| 가정 · assumption | 계산·시나리오가 전제로 둔 조건 | 설정 ID, 선택 이유, 민감도·미확인 여부 |
| 추측 · speculation | 검증되지 않은 설명 후보 | 미검증 표시와 검증에 필요한 자료 |
| 관측된 서사 · observed narrative | 정해진 채널·기간에서 참여자가 표현한 주장·우려 | 공개 발언 참조·원문 위치·선택 범위·중복 관계; 내용의 사실 검증 상태는 별도 |

관측 사실과 외부 사실은 모두 외부 출처를 가질 수 있다. 분류는 출처의 우열이 아니라 직접 관측 자료인지 문서에서 인용한 내용인지를 구분한다. 한 문장에 여러 유형이 섞이면 분리한다. 추측은 핵심 결론을 뒷받침하는 확인된 근거로 사용하지 않는다.

각 주장에 출처 등급과 검증 상태를 별도로 표시한다. 6단계 출처 우선순위와 확인 범위는 [리서치 신뢰성 규칙](research-integrity.md)을 따른다. “기업이 가이던스를 발표했다”, “커뮤니티에서 재고 부족 주장이 관측됐다”와 그 내용이 실제로 맞다는 주장은 별도다. 미검증·상충·동일 범위에서 반박된 주장을 구분하며, 확인 자료를 찾지 못한 것을 거짓이라고 표시하지 않는다.

비수치 주장도 원문 구절·위치·버전·시점과 연결한다. 같은 원자료를 반복 인용한 기사·게시물은 여러 독립 확인처럼 표현하지 않는다. 커뮤니티 관측은 선택한 공개 채널·기간의 서사이며 전체 투자자의 sentiment나 가격 예측으로 확장하지 않는다. 좋아요·조회수·언급 빈도는 정의된 표본의 관측일 수 있으나 사실 신뢰도·미래 수익 확률이 아니다.

## 4. 수치 표현

모든 금융 수치는 기간, 통화·단위, 출처 또는 계산 참조를 갖는다. 과거 표본수, 관측수와 유효 표본수, 비용·세금 포함 여부를 함께 제시한다. 자리수를 많이 보이는 것이 신뢰도가 높다는 뜻은 아니다.

- 과거 양의 수익 비율은 **정의된 과거 표본에서 관측된 빈도**로 표현한다.
- 미래 기대나 시나리오는 방법·가정·불확실성이 있는 별도 영역으로 분리한다.
- “예상 수익률”이라는 제목 아래 과거 평균을 그대로 넣지 않는다.
- 누락·해당 없음·검증 실패를 구분한다. `—`만 표시하지 않고 이유를 함께 쓴다.
- 서로 다른 기간·통화·배당 방식·비용 조건의 숫자를 우열 비교하지 않는다.
- 자료가 오래되었으면 요약에서 기준 시점을 표시한다. 신뢰도 점수 하나로 자료·방법·미래 불확실성을 덮지 않는다.
- 출처의 최신 값들을 모았어도 하나의 시점에서 동시에 이용 가능했던 자료인지 확인한다. 문서의 최신 작성일을 오래된 입력의 기준 시점으로 대신하지 않는다.
- 자산군마다 지원되는 손실·현금흐름 분석을 사용한다. 부동산의 낮은 거래 빈도에서 계산된 가격 변동성과 매일 거래되는 자산의 변동성을 그대로 위험 순위에 쓰지 않는다.
- 현재 매력도·집중 위험·배분 시나리오는 계산 정의와 자료가 지원되는 범위에서만 제시한다. 개인 조건이나 기대수익을 LLM이 채운 자동 투자비중은 게시하지 않는다.

## 5. 설명 원칙

전문 표현은 “자료에서 무엇을 봤는지 → 쉽게 말하면 무슨 뜻인지 → 무엇까지 말할 수 없는지” 순서로 풀어 쓴다. 예를 들어 천연가스 분석에서 재고·선물곡선·가격 추세를 쓴다면 각 자료가 공급 상황, 계약별 가격 차이, 최근 가격 움직임을 뜻한다는 설명을 붙인다. 실제 검증 결과가 없는데 이 조합이 좋은 성과를 냈다고 말하지 않는다.

“모델이 유망하다고 평가했다”, “역사적으로 반드시 회복한다”, “젊으니 손실을 감수하면 된다” 같은 문장은 근거를 대체할 수 없다. 위험 설명도 면책 문구로만 처리하지 않고 어떤 경로로 손실이 발생하는지 보여 준다.

반대 자료가 없으면 조사 범위를 명시한다. 해석을 반박하는 질문을 본문에 포함하며, 사용자가 근거를 따라 자신의 표현으로 판단할 수 있게 한다.

정성 해석은 “이 근거는 이 조건에서 이 논리를 지지하지만, 이 반대 설명을 배제하지 못한다”처럼 범위를 드러낸다. “출처가 있으므로 검증됨”이나 “여러 에이전트가 동의했으므로 유망함”으로 논리 검토를 대신하지 않는다. LLM이 작성한 문장은 검토할 초안이며 근거 등급·검증 상태·결론 강도를 바꾸는 권한을 갖지 않는다.

사용자 적용은 시장 해석 뒤에 별도로 연결한다. 장기적 기회가 보여도 가까운 자금수요·부채·기존 집중 노출 때문에 사용자에게는 적절하지 않을 수 있다. 확인되지 않은 개인 조건은 질문 또는 조건부 설명으로 남긴다. 현재 정보가 부족한 것을 자산의 낮은 매력도와 혼동하지 않는다.

## 6. 정형 보고서 계약의 예

다음은 실제 분석이나 수익률 예시가 아니라 **필드를 보여 주는 템플릿**이다. 값은 유효한 근거 ID를 통해 코드가 삽입해야 한다.

```text
질문: {research_question}
판단 목적·기간·통화: {decision_context_and_comparison_frame}
정보 기준 시점: {as_of}
사용자 정보 기준 시점·버전: {profile_snapshot_reference}
상태: {run_status} / {limitations}

현재 중요한 변화와 위험
  {relevant_market_context_with_evidence_references}
  자료의 시점·범위와 미확인 전제: {context_limits}

조사할 대안과 조사 범위
  {candidate_alternatives_and_reasons}
  깊게 조사한 대상·제외한 범위: {research_plan_scope}

  {supported_comparison_or_non_comparability_reasons}

  {metric_name}: {rendered_value_with_unit}

  근거: {metric_evidence_id}
  배당·비용·세금 처리: {return_definition}

기회 가설과 쉬운 설명 [해석: 검토된 범위]
  {reviewed_claim_with_supporting_evidence_and_assumptions}
  이 근거가 답할 수 없는 질문: {inference_limits}

관측된 서사 [해당하는 경우]
  {observed_narrative_with_source_passages_and_sampling_scope}

  {counter_evidence_or_review_scope}

  {profile_constraints_and_supported_exposure_findings}

  {krw_result_or_block_reason}
  {fx_policy_and_account_tax_scope}

  {conditions_sources_and_recheck_time}
  {missing_information_and_focused_follow_up_research}

  {limited_conclusion_or_reason_to_withhold_conclusion}

  {run_id} / {input_manifest} / {method_version} / {source_and_claim_records}
```

근거 참조가 끊어지거나 기간·단위가 맞지 않으면 해당 문장을 렌더링하지 않는다. 임의의 예상 값이나 LLM이 계산한 수치로 빈칸을 채우지 않는다. 비수치 주장도 범위·시점·지지 근거가 연결되지 않으면 사실로 게시하지 않는다. 자동 구조 검증 통과는 정성 논리의 타당성을 보장하지 않으므로 해석에 검토 상태와 한계를 표시한다.

핵심 비교에 필요한 자료가 없거나 상충을 해소하지 못했거나 의미 있는 차이를 찾지 못했다면 “현재는 강한 결론을 내릴 근거가 부족하다”를 정상 결과로 보고한다. 어떤 이유인지, 독립적으로 유효한 관측은 무엇인지, 무엇을 추가로 확인해야 하는지 함께 설명한다. 실행 오류와 정상적인 결론 유보는 구분한다.

## 7. 시각화

그림은 조사 질문을 설명할 때 사용한다. 대안별 수익 원천·위험·유동성·사용자 제약은 비교 표로, 지지·반대 주장과 아직 끊어진 근거는 관계도로 보여 줄 수 있다. 동일한 정의가 없는 자산을 종합점수나 레이더 차트로 정밀하게 비교하는 인상을 주지 않는다.

지원되는 정량 질문에서는 KRW와 원 통화의 누적 가치·낙폭을 같은 기간의 별도 경로로 제시해 통화 영향을 설명할 수 있다. 필요하면 수익 분포, 실패 기간, 비용 민감도 등을 추가한다. 통화·수익 정의·기준값·누락 구간·비교 조건을 축과 설명에 명시한다. 세로축이나 기간 선택으로 유리한 결과만 강조하지 않는다. 커뮤니티 지표를 표시하면 선택한 표본의 관측임을 붙이고 전체 시장의 심리로 해석하지 않는다.

## 8. 핵심 용어 풀이

| 용어 | 쉬운 한국어와 주의점 |
| --- | --- |
| Expected return | 미래 결과의 평균에 대한 추정. 과거 평균과 같다는 보장은 없음 |
| Downside risk | 불리한 결과의 가능성과 크기. 가격 변동, 영구 손실, 유동성 위험 등을 구분 |
| Volatility | 수익률이 얼마나 흔들렸는지 나타내는 지표. 모든 손실 위험을 나타내지는 않음 |
| Maximum drawdown | 관측 경로에서 고점 이후 가장 깊게 내려간 손실. 미래 손실 상한은 아님 |
| Total return | 가격 변화뿐 아니라 정의된 배당·이자 재투자 등을 포함한 성과 |
| Momentum | 최근 가격 움직임이 이어지는지 보는 분석. 상승 지속의 보장은 아님 |
| Market regime | 금리·변동성 등 시장 상태를 구분한 것. 상태 정의와 판단 시점이 필요 |
| Historical analogue | 미리 정의한 조건이 비슷했던 과거 사례. 선택 방식에 따라 결론이 달라짐 |
| Forward return | 지정한 과거 기준 시점 이후 구간의 수익. 미래 수익 예측과 구별 |
| Backwardation | 가까운 만기의 선물 가격이 먼 만기보다 높은 상태. 현물·선물 투자 성과를 동일시할 수 없음 |
| Volatility drag | 수익률이 흔들릴 때 산술평균과 복리 성과가 벌어질 수 있는 효과 |
| Path dependency | 시작·끝 가격뿐 아니라 중간 경로에 따라 결과가 달라짐 |
| Invalidation condition | 확인되면 기존 해석의 전제나 논리를 다시 검토해야 하는 조건 |
| Tracking difference / error | 지수 대비 성과 차이 / 그 차이의 변동성. 상품 보수와 동일한 개념은 아님 |
| Point-in-time data | 당시 실제로 알 수 있었던 버전과 이용 가능 시점이 보존된 자료 |
| Out-of-sample | 방법 선택에 사용하지 않은 자료에서의 평가. 반복해서 보고 수정하면 의미가 약해짐 |
| Cross-asset research | 여러 자산의 수익 원천·위험·투자 조건을 관련 대안과 함께 검토하는 연구. 같은 지표로 일괄 순위화하는 뜻은 아님 |
| Opportunity cost | 한 선택 때문에 포기하는 다른 대안의 가능한 이익과 선택권. 미래 차이는 가정과 불확실성을 가짐 |
| Market narrative | 참여자들이 시장을 설명하는 이야기나 기대. 널리 퍼졌다는 것과 사실이라는 것은 다름 |
| Comparison frame | 통화·기간·수익 정의·유동성·비용·위험을 맞추거나 차이를 공개하는 비교 조건 |

## 9. 설명 품질 검증

보고서 검토에서는 금융 정확성, 질문 관련성, 근거 추적, 단위·시점, 반대 논리, 불확실성 공개와 함께 사용자의 이해를 확인한다. “무엇을 봤나, 왜 중요한가, 어떤 대안과 비교했나, 내 조건에서 무엇이 달라지나, 어떤 위험인가, 무엇이 바뀌면 재조사하나”에 답할 수 없는 보고서는 질문과 근거 연결을 수정한다.

검토한 자료 수나 생성된 결론 수를 품질 지표로 삼지 않는다. 핵심 주장에 뒷받침되는 원문·계산이 있는지, 중복 근거를 과대평가하지 않았는지, 필요한 반대 자료를 검토했는지, 비교 불가·개인 정보 누락·강한 결론 유보를 정직하게 표시했는지 평가한다. 사람의 의미 검토나 다른 LLM의 평가도 금융적 타당성·미래 수익을 자동 보증하는 장치라고 설명하지 않는다.
