# 한국 투자자 맥락

현재 합성 오프라인 MVP는 아래 원칙 중 알려진 기본 맥락과 미확인 정보에 따른 판단 제한을 구현한다. 총자산·비상자금·부채·주택 필요자금·보유 배분·월 투자액·위험 감당 능력이 unknown인 예제로 개인 배분 결론을 제한한다. 실제 공개 source 검증 MVP도 같은 연구 모델로 연결되며, 그 사례에서는 **KRW 외의 개인 정보를 unknown**으로 두고 자산 추천·배분 비중을 만들지 않는다. 현재 [ask Portfolio Review MVP](research-orchestrator.md)는 명시적 KRW 자기보고 평가액·전체성·현금으로 계산 가능한 보유 구성과 부채 차감·자금수요 명목 합계를 추가했다. 중복 노출 look-through·시점별 자금 지급 가능성·KRW 성과 환산·세금/계좌·특정 부동산 가치는 미지원이다.

[실제 source 사례](../examples/real_world_case/README.md)는 2024-09-18 Fed 발표와 커뮤니티 발언을 2026-10-04라는 고정 기준일로 사후 확인하는 4개 출처·6개 근거·4개 주장의 검증 경로다. 발표된 인하 폭의 좁은 수치 확인과 맥락·부분 확인·미확인을 구분하며 현재 시장 매력이나 한국 사용자 적합성의 평가로 사용하지 않는다. 과거 미국 정책 발표가 정확하더라도 최신 한국 자금수요·환율·상품·과세·보유 조건을 대신하지 않는다.

## 1. 사용자 맥락은 필요한 판단의 시작 입력이다

현재 [거시 보고서](../examples/macro_case/macro_snapshot.md)는 미국 CPI·국채 시장금리와 원/달러 기준환율을 나누어 보여 준다. `KRW_per_USD` 감소는 같은 달러를 사는 데 필요한 원화가 줄었다는 관측이며 미국 주식의 사업환경이나 사용자의 전체 원화 수익률을 뜻하지 않는다. 환헤지·매매환율·자산가격·비용·세금·보유기간이 없으므로 실현 수익률과 개인 배분은 계산하지 않는다. 이번 경로의 ProfileSnapshot은 KRW만 known이며 재산·부채·자금수요는 unknown으로 제한한다.

시장에서 상대적으로 매력적인 자산과 지금 이 사용자에게 적절한 자산은 서로 다른 판단이다. 질문에 개인 판단이 포함되면 두 근거를 구분해 연결한다. 일반 시장·사업 Deep Dive에 전체 개인 원장을 먼저 요구하지 않는다. Portfolio Review는 실제 보유·현금·부채·자금 제약부터 시작하고, 자산 자체의 매력·기존 과다 노출·추가 보유의 전체 효과를 따로 검토한다. 자산이 저평가되었다는 근거만으로 주택 구입에 필요한 돈을 투자할 수 있다고 결론 내리지 않으며, 사용자의 제약만으로 그 자산의 시장 매력이 낮다고 평가하지 않는다. [독립 모드 계약](research-modes.md)을 따른다.

`ResearchBrief`는 정보 기준 시점, 실제 투자 질문, 관련 기간·대안과 함께 `ProfileSnapshot`을 참조한다. 사용자 맥락이 판단에 필요하면 조사 범위와 비교 조건을 정하는 입력으로 사용한다. Scan의 후보 선정이나 전체 사용자 정보 확보를 모든 모드의 선행 관문으로 두지 않는다. 예를 들어 주택 구입 자금의 보존을 조사할 때와 장기 추가 투자 자금의 사용을 조사할 때는 같은 자산이라도 필요한 유동성과 검토 기간이 다르다.

`ProfileSnapshot`은 사용자가 확인한 정보의 기준 시점·버전·확인 상태를 보존한다. 이전 요청에서 사용자가 밝힌 대한민국 세법상 거주자, KRW 기준 통화, 1998년생, 자산 축적기, 안정적인 근로소득, 장기 투자 가능 등의 기본 맥락은 자기보고 정보로 기록한다. 외부 검증된 사실이나 앞으로도 유지될 상태로 취급하지 않으며, 출생연도·소득 안정성의 서술에서 소득 규모나 실제 투자 가능액을 추정하지 않는다. 적용 시점에 필요한 과세 상태·계좌 자격 등은 그 확인 수준과 미확인 조건을 구분한다.

| 입력 범주 | 연구에 필요한 정보 | 사용하는 방식 |
| --- | --- | --- |
| 생활·과세 기준 | 거주지·세법상 거주자 상태, 생활비 통화, 기준 통화, 적용 가능한 계좌 | 과세 규칙·환율·투자 접근성의 적용 범위 확인 |
| 보유자산 | 금융자산, 현금·현금성 자산, 부동산, 경제적 노출, 보유·평가 시점 | 추가 투자와 기존 포트폴리오의 집중위험·중복 노출 구분 |
| 현금흐름 | 근로소득의 안정성, 필수 지출, 월 추가 투자 가능액, 비상자금 | 손실 중에도 생활비·의무지출을 충족할 수 있는지 검토 |
| 큰 자금수요 | 금액·시점·확실성, 주택 구입 계획, 교육·이사 등 사용자가 밝힌 필요 | 투자 기간, 유동성·강제 매도 가능성, 별도 자금 보존 필요 확인 |
| 부채 | 잔액, 금리·변동 조건, 만기·상환 일정, 중도상환 비용, 담보 조건 | 투자·현금 보유·부채 상환의 기회비용과 현금흐름 비교 |
| 투자 기간·접근 제약 | 자금별 사용 시점, 허용 상품·계좌, 잠금·출금 제약 | 검토 대상과 실제로 이용 가능한 대안 제한 |
| 위험 감당 능력 | 자금 부족·소득 중단·손실 상황에서 버틸 수 있는 자원과 의무 | 경제적으로 견딜 수 있는 손실과 유동성 위험 검토 |
| 위험 감수 의향 | 사용자가 밝힌 심리적 불편·손실 허용 의향 | 감당 능력과 별개로 기록하고 충돌을 공개 |
| 주거 목적 | 실거주 필요, 예상 거주 기간, 지역·직장 제약, 주택 보유·구입 계획 | 투자수익과 주거 편익을 구분하고 대체 주거 선택과 비교 |

필수 정보가 미확인이라면 `unknown`으로 남기고 어떤 개인화 판단이 제한되는지 표시한다. 월 투자 가능액을 소득에서 임의 추정하거나, 부채가 입력되지 않았다는 이유로 무부채라고 가정하지 않는다. 독립적인 시장 조사와 대안 비교는 계속할 수 있지만, 자금수요·부채·보유자산이 필요한 사용자 적절성이나 포트폴리오 판단은 해당 범위에서 차단한다. 입력된 보유자산이 전체인지 일부인지도 확인하며, 일부 자료만으로 전체 포트폴리오의 분산이나 안전성을 확정하지 않는다.

출생연도, 안정적인 근로소득, 장기 보유 의향, 높은 변동성 감수 의향은 자산의 미래 기대수익이 높다는 근거가 아니다. 사용자 한도는 사용자가 정한 제약 또는 명시적으로 확인한 방법으로 관리한다. 나이로 투자 비중이나 레버리지 허용을 자동 결정하지 않는다.

## 2. 자본 배분과 기회비용의 비교

실제 [Opportunity Map](opportunity-map.md)은 사용자가 밝힌 기본 맥락을 자기보고로 기록하고 총자산·부채·비상자금·필요 자금·월 투자액·보유범위·위험 감당 능력을 UNKNOWN으로 유지한다. 성장·변동성 감수 의향에서 매력·비중을 도출하지 않는다. 한국 국채 시장금리·수출·주택 정책배경과 미국 국채·주식·환율 조건은 별도로 비교하고, 한국 부동산 지역가격과 계좌별 세금이 부족하면 관련 개인화·세후 결과를 유보한다.

`ComparisonFrame`은 같은 사용자 자금에 대해 비교하는 대안, 공통 투자 기간, KRW 평가 기준, 유동성 필요, 비용·세금의 포함 범위를 명시한다. 주식·채권·현금·원자재·암호자산·부동산을 모두 항상 분석하지는 않는다. 직접 Compare는 사용자가 제시한 대안에서 시작하고, 후보 탐색은 Scan이 요청된 경우만 한다. 현금 유지, 추가 투자 보류, 부채 상환도 질문에 관련된다면 대안에 포함한다.

현재 국채 수익률, 현금 상품의 조건, 신용 스프레드, 물가, 환율 등은 실제 비교에 필요한 경우에만 사용한다. 계약상 금리·만기수익률·과거 수익률·미래 가정 수익률은 서로 다른 근거다. 서로 다른 기간이나 유동성·신용·통화 위험을 숨긴 채 하나의 기대수익 순위를 만들지 않는다. 부채 상환의 효과 역시 금리 변경, 상환 일정, 비용, 적용 가능한 세금, 상환 후 남는 유동성을 확인한 범위에서 계산한다.

포트폴리오 검토는 개별 자산의 낙폭뿐 아니라 KRW 생활비 부족, 불리한 시점의 강제 매도, 소득과 자산의 동시 악화, 통화·산업·지역·주택 집중, 유동성·영구 손실 경로를 포함한다. 한국 주택·한국 주식·한국 근로소득처럼 여러 항목이 같은 경제 환경에 노출될 수 있다는 가설은 검토할 수 있지만, 검증하지 않은 상관계수나 위기 손실 확률을 만들지 않는다. 해외 자산도 환율 때문에 원화 의무지출과 어긋날 수 있다.

### 자산배분 시나리오는 판단 도구다

`AllocationScenario`는 사용자가 제시했거나 명시적으로 정의한 자금 배분 대안을 비교하는 계약이다. 현재 보유 구성, 새로운 자금의 용도, 배분 금액·비중, 적용 기간, 유동성 필요, 비용·세금 상태, 가정과 참조 근거를 보존한다. 금액 합계와 비중 합계, 추가 투자 전후의 노출, 알려진 계약 현금흐름, 명시된 가격·환율 충격의 영향을 계산할 수 있다. 계약상 현금흐름에도 불이행·변동금리·인출 제약 등 확인된 조건을 표시한다. 입력과 적용 가능한 방법이 없는 값은 계산하지 않는다.

미래 가격이나 금리 변화는 명시적인 가정이며 예측이나 발생 확률이 아니다. 시나리오를 여러 개 생성했다는 이유로 기대수익의 분포나 최적 비중을 얻었다고 설명하지 않는다. 서로 다른 자산에 보편적인 수익률을 넣어 자동 최적화하거나, 부족한 정보를 LLM이 채워서 사용자에게 배분 비중을 제시하지 않는다. 비교 결과는 장단점, 집중·유동성 제약, 기회비용, 확인이 필요한 가정과 판단 유보를 보여 준다.

## 3. KRW 기준 분석

해외 자산은 원 통화 결과와 KRW 결과를 나란히 보여 준다. 환율 방향과 평가 시점을 기록한다.

USD로 평가된 외국 자산의 가치 경로에서 외부 자금 입출금이 없고, 환헤지·세금·거래 비용을 제외한 단순 비교라면 다음 관계를 쓸 수 있다.

`1 + R_KRW = (1 + R_USD) × (FX_end / FX_start)`

여기서 `FX`는 **USD당 KRW**, `R_USD`는 같은 기간의 USD 가치 수익률이다. 배당 재투자 총수익 지수를 사용한다면 그 재투자 정책도 일치해야 한다. 이 식은 실제 환전 거래·세금·입출금이 있는 개인 계좌의 실현 수익을 대신하지 않는다.

- 환율 변동률을 자산 수익률에 단순히 더하면 교차 효과를 놓친다.
- KRW 수익과 낙폭은 KRW 가치 경로에서 직접 계산한다. USD 최대 낙폭을 환율 한 번으로 변환하지 않는다.
- 주식과 환율의 평가 시점·휴장일 차이를 명시한다. 미래 환율로 이전 가격을 채우지 않는다. 과거 값을 사용하는 정렬도 허용 기간과 이유가 필요하다.
- KRW로 거래되는 국내 ETF 가격에는 상품의 환노출이 이미 반영될 수 있다. 해외 기초지수의 환율 효과를 다시 더하지 않는다.
- 환헤지 상품에는 단순 비헤지 환산식을 적용하지 않는다. 헤지 비율·비용·정책과 실제 상품 수익 경로를 확인한다.
- 다른 통화에도 같은 방향 정의를 적용한다. 거래소의 스테이블코인 표시를 확인 없이 USD 표시로 바꾸지 않는다.

과거 가치 경로를 비교하는 분석은 지원 조건에 따라 외부 자금 입출금 없는 경로로 제한할 수 있다. 이는 전체 최소 리서치 시스템의 정의가 아니다. 향후 실제 개인 성과는 거래·배당·환전·세금의 날짜별 현금흐름 원장으로 계산하며 시간가중 성과와 금액가중 성과를 구분한다.

## 4. 같은 노출을 얻는 상품·계좌 비교

미국 상장 ETF 직접투자, 국내 상장 관련 ETF, ISA 또는 연금계좌 내 상품은 비교 후보가 될 수 있다. 다음 조건을 확인하기 전에는 같은 투자 대안이라고 단정하지 않는다.

| 비교 축 | 확인할 정보 |
| --- | --- |
| 경제적 노출 | 추종 지수·실물·선물, 구성·운용 방식, 기준 시점 |
| 상품 구조 | ETF/ETN 등 종류, 복제 방식, 환헤지, 옵션 활용, 발행기관 위험 |
| 비용 | 실제 거래 수수료, 환전 비용, 호가 차이, 운용 보수, 추가 비용 |
| 성과 의미 | 배당·재투자·선물 교체·보수의 포함 여부, 추적 차이와 오차 |
| 거래 접근 | 계좌에서 보유 가능한지, 최소 단위, 거래 시간·유동성, 상품 이용 제한 |
| 세금 | 소득 종류, 원천징수, 실현 여부, 개인별 합산·공제·상계 등 확인된 규칙 |
| 계좌 조건 | 가입·납입·보유·출금 조건, 사용자의 자격과 남은 한도, 유동성 제약 |
| 사용자의 자금수요 | 투자 기간, 예상 출금 시점, 불확실한 현금흐름 |

ISA·연금저축·IRP의 현행 요건·한도·세율은 이 문서에서 확정하지 않는다. 장기 계좌의 효과를 세제 혜택만으로 평가하지 않고 출금 제약과 필요한 자금 시점을 함께 확인한다.

비교 결과는 통화·기간·배당 처리·가정이 같은 경우에만 수치로 나란히 제시한다. 자료가 부족하면 후보별 확인·미확인 항목을 보여 주는 비교표로 제한한다. 세후 단일 순위나 최적 계좌를 자동 출력하지 않는다.

## 5. 비용과 세금의 처리

비용후·세후 결과는 별도 실행 조건이다. 거래 날짜·수량·가격, 환율, 배당·이자, 비용, 확인된 과세 규칙과 사용자 상태가 충분해야 한다. 세금 계산에 쓰는 소득 분류·환산 기준은 일반 성과 환산과 같다고 가정하지 않는다.

ETF 가격이나 총수익 자료에 운용 보수가 이미 반영되어 있으면 다시 차감하지 않는다. 거래 비용·환전 비용처럼 추가로 발생하는 비용은 별도 기록한다. 외국 원천징수와 국내 세금도 단순 합산하지 않고 적용 가능한 공제·정산 규칙을 확인한다. 미확인 세금이나 비용을 0으로 넣지 않는다.

세전, 비용후, 세후 결과를 서로 다른 상태와 가정으로 표시한다. 세후 분석을 요청했는데 규칙이나 개인별 입력이 부족하면 그 결과는 `blocked`다. 독립적인 세전 분석을 보여 줄 수 있어도 이를 세후 결과로 바꾸어 부르지 않는다.

### 세법·계좌 정책의 버전 계약

| 필드 | 역할 |
| --- | --- |
| 정책 ID·버전 | 어느 규칙으로 계산했는지 식별 |
| jurisdiction | 한국 및 필요한 해외 관할·적용 범위 |
| investor status | 적용 가능한 거주자·납세자 조건과 미확인 상태 |
| account type·instrument/income type | 계좌·상품·소득별 적용 조건 |
| effective_from / effective_to | 거래·소득 시점에 유효한 구간과 경과 규정 |
| source | 공식 문서 URL·조항·문서 버전 등 확인 근거 |
| published_at / retrieved_at | 공표·확인 시점; 과거 정보 재현에는 당시 이용 가능성도 필요 |
| verification status | 확인, 미확인, 대체됨, 검토 필요 등의 상태 |
| calculation semantics | 과세 사건, 과표, 환산·반올림·공제·합산·신고 시점의 정의 |

공식 법령·과세기관·계좌 제도 문서를 우선한다. 금융기관의 실제 거래 비용·상품 제한은 해당 기관 문서로 확인하고 세법 출처와 구분한다. LLM 기억에서 세율을 가져오지 않는다.

규칙은 유효 구간의 중복·공백을 검증하고, 규칙 ID·버전을 실행 기록에 고정한다. 현재 제도로 과거를 재계산하거나 장기간의 세후 미래를 확정하지 않는다. 미래 제도 유지 가정을 쓴다면 명시적인 시나리오로만 제시한다. 규칙을 갱신해도 과거 실행은 보존한다.

## 6. 한국 부동산은 별도의 연구 방법을 쓴다

한국 부동산은 주식처럼 거래소 가격 경로와 기술적 지표만으로 평가하지 않는다. 지역·단지·유형·면적·노후화·권리·거래 조건·보유 목적을 식별하고, 질문에 필요한 항목만 조사한다. 전국 평균이 특정 주택의 평가액이나 개인의 매도 가능 가격이 되지는 않는다.

| 조사 영역 | 필요한 경우 검토할 내용 | 검증·해석의 경계 |
| --- | --- | --- |
| 거래·가격 | 실제 거래가격, 거래량, 호가, 거래 취소·정정, 비교 가능한 지역·면적·연식 | 호가와 실거래를 구분하고 신고 지연·개정·적은 표본·선택편향 표시 |
| 임대·현금흐름 | 전세가격·전세가율, 임대료, 공실, 유지·수선·관리 비용 | 매매·전세 비교 시점과 대상 일치 확인; 보증금은 임대수익이 아니며 반환 의무 반영 |
| 수급·가구 | 공급, 입주물량, 미분양, 인구·세대수, 주변 경쟁지역 | 발표 계획과 실제 착공·입주·실현 수요를 구분 |
| 금융·정책 | 금리, 대출조건, 만기·상환 방식, 정책·규제, 거래·보유 비용 | 사용자·주택에 실제 적용되는 조건과 유효 시점 확인 |
| 입지·주거 | 일자리 접근성, 교통, 신규 철도·GTX, 학군, 상권, 지역 개발계획, 신축·구축 차이 | 제안·계획·승인·착공·개통 등 단계와 불확실성 구분; 주거 편익을 투자수익으로 합산하지 않음 |
| 지역 의견 | 지역 커뮤니티의 관심·우려, 경쟁지역에 관한 주장, 개발 기대 | 주장과 의견을 분리하고 공식 계획·거래·수급 자료로 가능한 범위에서 검증 |

지역 커뮤니티에서 반복되는 개발 기대나 가격 주장은 새로운 연구 질문의 단서다. 게시글 수로 지역 전체 수요나 가격 상승 확률을 추정하지 않는다. 중개·홍보 이해관계, 중복 게시, 표본 구성과 관찰 기간을 표시한다. 하위 출처의 중요 주장은 공식 거래자료, 정부·지자체 계획, 사업 주체의 공개 자료 등 해당 주장에 적합한 상위 자료로 확인하며, 확인 실패는 사실 확정으로 이어지지 않는다.

부동산 비교는 취득·보유·처분 비용, 금융비용, 공실·유지비, 임대 현금흐름, 받은 전세보증금의 반환 의무와 지급한 보증금의 회수 위험, 대출 갱신·상환, 매도 소요기간과 유동성, 다른 투자 대안의 기회비용을 검토한다. 모든 금액은 입력과 확인된 규칙이 있는 범위에서만 계산한다. 받은 전세보증금과 차입금을 자신의 투자자본이나 자유 현금으로 취급하지 않는다.

실거주 편익은 주거 안정, 통근, 교육·생활 환경처럼 사용자의 선호와 제약으로 따로 기술한다. 별도의 명시적 평가 방법 없이 이를 예상 자본차익이나 임대수익에 더하지 않는다. 자가 구입·임차 유지·금융자산 투자 비교에서는 같은 주거 필요와 기간을 두고 자금·부채·의무지출을 확인한다. 부동산 실거래의 낮은 관측 빈도와 거래 선택편향 때문에 낮게 보이는 가격 분산을 주식의 일별 변동성과 직접 동일시하지 않는다.

## 7. 레버리지와 손실 회복

기초자산 분석 이후에도 레버리지 상품은 별도의 자료·방법·사용자 제약을 요구한다. 재설정·경로·복리·청산 조건을 모르는 상품은 계산 범위에 넣지 않는다. 손실 회복 계산은 외부 자금 투입 없이 같은 자본이 회복하는 단순 조건인지 명시한다. 이는 상품 생존이나 사용자의 버틸 능력을 증명하지 않는다.

영구 손실, 거래소·발행기관 부도, 시장 폐쇄, 유동성 상실 등은 가격 변동성만으로 포착되지 않는다. 통계가 제공되지 않는 위험도 계약·재무·운영의 확인 가능한 근거와 시나리오로 설명한다. 출처 없는 파산 확률을 생성하지 않는다.

## 8. 도입 순서와 개인정보

첫 최소 리서치 시스템은 오프라인 `ResearchBrief`에 필요한 `ProfileSnapshot`, 비교 대안과 `ComparisonFrame`, 근거·반대 근거를 연결하여 한국어 연구 브리프를 만드는 경로다. 단일 ETF 수익률 계산을 완료 목표로 삼지 않는다. 가상의 사용자·시장 자료를 사용하는 합성 fixture로 사용자 맥락이 조사 범위와 보고서 한계에 실제로 반영되는지 검증할 수 있다. 실제 개인정보나 계좌 연결 없이 구현 검증이 가능하다는 뜻이며, 개인화 판단에 사용자 정보가 불필요하다는 뜻이 아니다.

최소 브리프도 확인된 사용자 제약과 미확인 항목을 보여 주고, 비교 가능한 근거·비교 불가능한 이유, 중요한 위험·기회비용, 추가 관찰 조건을 설명한다. 숫자 계산은 검증된 입력·방법이 있을 때만 추가한다. 부동산·세후 성과·배분 시나리오 등 미지원 분석은 범위를 공개하고 후속 단계에서 고유 입력·방법을 구현한다. 자세한 단계와 완료 기준은 [로드맵](roadmap.md)을 따른다.

공개 자료는 검토한 URL을 `sources acquire`로 읽고 권리·시점·원문/구절·해시·실패 상태를 snapshot으로 남긴다. `sources replay`는 pins의 고정 snapshot을 인터넷 없이 기존 연구 모델과 보고서로 연결한다. source와 근거의 provenance, 최신성·unknown·상충 맥락을 유지하며 획득일을 공개일이나 현재 사용자 정보의 확인일로 대신하지 않는다. 이 공개 source 경로는 개인 계좌·잔액·부채 원장을 수집하는 기능이 아니다. 실행과 보존 한계는 [source 획득 안내](source-acquisition.md)에 둔다.

실제 개인 자료는 해당 연구에 필요한 범위로만 입력받는다. 민감한 개인 원장은 별도로 보관하며 버전 관리·공유 보고서·로그에서 제외한다. `ProfileSnapshot`의 참조·확인 상태만으로도 실행을 추적할 수 있도록 하고, 연구 공유용으로는 개인 식별자·정확한 잔액 등 불필요한 정보를 제거한다. 외부 모델에는 기본적으로 개인 원장을 보내지 않으며, 설명에 필요하다면 사용자가 확인한 최소 제약만 제공한다. 모델 전송·보고서 공개 범위와 원본 보관 범위는 서로 다르게 관리한다.
