# 포트폴리오 규칙용 백테스트 설계안 (구현하지 않음)

2026-11-02. [사전 등록 라이브러리](../examples/strategy_library/README.md)의 15개 후보가 "시험 불가"인 이유 중 하나를 풀기 위한 **설계안**이다. 코드는 없고, 어떤 후보도 이 문서로 시험하지 않았다. 구현 전에 아래 [결정이 필요한 것](#결정이-필요한-것)을 사용자가 정해야 한다.

## 왜 지금 엔진으로는 안 되는가

현재 백테스트(`pit_event_backtest_v1·v2`)가 표현하는 것은 하나다: **신호가 켜질 때 한 자산을 사서 정해진 기간 보유한 결과를 다른 시장과 비교한다.** 아래 규칙은 이 형태가 아니다.

| 규칙 | 표현하지 못하는 이유 |
| --- | --- |
| 추세 + 현금 대피, 이중 모멘텀 | 항상 투자 중이고, 꺼지면 다른 자산(현금·채권)으로 **옮겨 간다.** 비교 대상이 "같은 자산 단순 보유"인데 현재 엔진은 비교 시장이 후보와 다른 상품이어야 한다 |
| 변동성 목표 | 비중을 연속으로 조절하고 현금 다리가 필요하다 |
| 정기 리밸런싱(60/40, 영구 포트폴리오, 올웨더) | 여러 자산을 동시에 보유하고 비중을 되돌리는 거래 비용이 핵심이다 |
| 이자 자산 기본 보유 + 위험자산 조건부 편입 | 기본 보유 자산 위에 조건부로 얹는 구조라 기회비용(이자)이 수익의 일부다 |
| 정액 적립 | 현금 흐름 시점이 전략의 본체다 |

현금 대피 규칙의 가치는 "수익이 더 높다"보다 "낙폭이 작다"에 있는 경우가 많다. 평균 초과수익만 보는 지금 문턱으로 평가하면 이런 규칙의 효과를 놓치거나 반대로 **노출이 줄어서 생긴 낮은 위험을 능력으로 오인**한다. 그래서 별도 엔진과 별도 문턱이 필요하다.

## 제안: `pit_overlay_backtest_v1`

### 입력

- **규칙**: 결정 시점에 알려진 정보만 읽어 목표 비중(합계 100%, 음수 없음)을 내는 결정적 함수. 이번 버전은 **레버리지 없음, 공매도 없음.** 레버리지·인버스 상품은 그 상품 자체의 가격 이력이 있을 때만 하나의 다리로 넣고, 기초자산 수익률에 배수를 곱해 만들지 않는다.
- **다리(legs)**: 각 다리는 원화 총수익이 정의된 실행 가능한 상품 이력이다. 비교 시장 전용 NAV 계열은 다리로 쓰지 못한다(체결 가격이 아니다).
- **달력**: 월말 종가에서 결정하고 **다음 관측**에 체결한 것으로 계산한다(현재 엔진과 같은 규칙).
- **비용**: 거래한 금액에 양방향 비용을 곱한다. 리밸런싱·대피 이동마다 낸다. 규칙을 등록할 때 고정한다.

### 비교 (결과가 아니라 비교 대상이 핵심이다)

| 기준선 | 막으려는 오류 |
| --- | --- |
| 위험자산 100% 단순 보유 | 낙폭이 작아진 대신 포기한 수익을 숨김 |
| **같은 평균 노출의 고정 비중 혼합**(예: 대피 규칙이 평균 62%를 투자했다면 위험자산 62%+이자 자산 38% 고정) | 노출을 줄여서 생긴 낮은 변동성을 규칙의 능력으로 오인 |
| 이자 자산 100% | 위험을 질 만한 보상이 있었는지 |
| 같은 규칙을 비용 0으로 | 비용이 우위를 지웠는지 |

### 지표와 통계

- 원화 총수익, 연환산 수익률, 월 수익률의 변동성, 월별 관측 기준 최대 낙폭(일중 낙폭은 증명하지 못한다), 회전율, 투자 비율, 최악의 12개월.
- 우위 판정은 위의 **같은 평균 노출 혼합**과의 월별 수익 차이에 대한 **정상 블록 부트스트랩** 신뢰구간(블록 길이는 등록 시 고정)으로 한다. 월 수익은 자기상관과 국면 의존이 커서 관측 월 수가 곧 독립 표본 수가 아니다. 보고서에 유효 표본이 작다는 경고를 항상 붙인다.
- 여러 후보를 시험하므로 [섀도 추적](shadow-tracking.md)과 같은 방식으로 **등록 이후의 전향 기록**만 승격 근거로 쓰고, 시험 후보 수 K로 보정한다. 포트폴리오 규칙의 섀도는 "금액 0의 가상 포트폴리오"를 판단 시각마다 목표 비중으로 기록하고 다음 관측 가격으로 평가한다.
- 합격선은 등록 시 고정하며 낙폭 감소와 수익 포기를 함께 보이는 표로 판정한다. 하나의 점수로 합치지 않는다.

### 시점 누수·정의 검사(필수 테스트)

미래 정보로 비중 결정, 통화 역전, 분배금 이중 계산, 다리 날짜 정렬 오류, 결측·중복, 가격과 총수익 혼동, 같은 평균 노출 기준선의 노출 계산 오류, 거래비용 부호, 리밸런싱 직전 비중 드리프트 계산. 손으로 검산할 수 있는 2~3개 다리의 합성 경로를 쓰고, 각 안전장치를 끄는 변이 점검으로 테스트가 실패하는지 확인한다.

## 필요한 이력 제공자

현재 등록된 가격 제공자는 Upbit BTC·ETH, KODEX 발행사 JSON(KODEX 200TR·MSCI KOREA TR·코스피TR 3종), TIGER 발행사 NAV(미국 S&P500·나스닥100, 비교 시장 전용)뿐이다.

| 필요한 다리 | 지금 | 비고 |
| --- | --- | --- |
| 이자 자산(CD·MMF·단기채) 원화 총수익 | **없음** | 기준금리·CD금리 같은 **금리 지표를 수익 이력으로 바꾸어 쓰지 않는다**(기존 원칙). 발행사가 분배 정책과 NAV를 공개하는 CD금리·단기채 ETF를 같은 방식(분배 정책 재확인 + 분배 이력 대조)으로 검토해야 한다 |
| 국채/채권 원화 총수익 | 없음 | 분배금을 지급하는 상품이면 TIGER와 같은 NAV 대조가 필요하다 |
| 금 원화 총수익 | 없음 | 환율·헤지 여부를 정의해야 한다 |
| 미국 주식 **실행 가능한** 원화 총수익 | **없음**(TIGER NAV는 비교 시장 전용) | 분배금을 재투자하는 국내 상장 상품을 찾지 못했다([장기 이력](long-history.md)). 이 다리가 없으면 미국 주식이 들어간 규칙은 시험하지 못한다 |
| 개별 종목·요인 | 없음 | 시점 보장 재무 자료까지 필요하다 |

제공자마다 robots.txt, 이용 조건, 요청 제한, 재배포 권한을 확인하고 실제 응답은 커밋하지 않는다.

## 단계

1. **엔진 A**: 현재 있는 다리(KODEX 200TR, BTC, ETH)로 합성 경로 테스트와 변이 점검을 갖춘 엔진. 이자 다리는 합성 fixture로만 시험한다.
2. **제공자**: 이자 자산 원화 총수익 후보를 하나 검토해 계약을 추가한다(별도 요청 범위).
3. **섀도 포트폴리오 장부**: 가상 포트폴리오의 전향 기록과 승격 문턱. 사전 등록 장부와 해시 체인을 그대로 쓴다.

## 결정이 필요한 것

1. **현금 다리의 수익 정의.** 발행사 ETF NAV의 총수익을 쓸지(권장, 자료 계약 필요), 아니면 정책금리 누적으로 모형화할지. 후자는 가정이 크므로 사용자가 먼저 정해야 한다.
2. **결정 주기.** 월말만 허용하는 것을 제안한다(주간 결정은 비용과 자기상관 문제가 커진다).
3. **레버리지 없음 유지 여부.** 이번 설계는 없음으로 고정했다.
4. **합격선의 모양.** 낙폭 감소를 어느 정도의 수익 포기까지 허용할지는 위험 감당 능력이 아니라 사용자의 선택이다. 결과를 보기 전에 정해야 한다.

## 하지 않는 것

세금·계좌 유형(ISA·연금저축)의 효과, 개인 체결, 옵션·선물 다리, 종목 선택. 세율과 계좌 요건은 출처와 유효기간 없는 상수로 넣지 않는다.
